# Backend rules: architecture, design, persistence, configuration

How each context works today is in `docs/system-overview.md`; this file is what a change must keep true.

## Local first (Jakub 2026-10-28)
- Whatever can run in the browser runs there: rendering and computing from data the signed-in user already receives (QR codes, receipt PDFs, formatting, sorting and filtering a loaded list, summaries of the donor's own gifts, the encrypted copy on the device, for donors and administrators alike). The backend serves the data and keeps only what the browser cannot do: what grants or proves something (authentication, roles, rate limits, receipt numbers and the certified receipt data, pairing, the audit trail); what runs without a browser (the Fio import, scheduled jobs, e-mail, backups) or what the MCP connector also reads; aggregates over other people's data that a job without a browser or the connector needs (the monthly report, the administration's overviews, until the administration's pages compute them from the device copy); and validating every input again.
- A new endpoint that renders or computes what the frontend could do from data it already holds names its reason in the PR. Logic that runs on both sides is proved by one shared set of cases (`testing-shared-cases.md`).
- The server draws no QR code and no receipt PDF: no production class uses openhtmltopdf, PDFBox or ZXing (ArchUnit), and none is on the test classpath (`ServerDrawingLibrariesTest`). Photos for news and projects stay converted on the backend for now (Jakub 2026-10-28: few administrators).

## Contexts and layers
- Contexts `content`, `donors`, `donations`, `contact`, `operations`, kernel `shared` (what each owns: `docs/system-overview.md`). Per context: `domain` depends only on the JDK's core and domain packages (no Spring, JPA, Bean Validation, logging, JSON, JDBC, input streams or classpath resources; of `java.lang` only the value-level types listed in `DddLayeringRulesTest` and `System.arraycopy`, so no environment, system property, clock, thread, process, class loading or reflection; a list the domain needs, such as the common passwords or the backup key words, is read by infrastructure at startup and handed in as a value); `application` → domain; `infrastructure` → domain, application; `interfaces/rest` → application, domain and the `shared` infrastructure outside persistence, never a context's adapters or a port that persistence implements. Contexts never depend on each other, and `shared` never imports a context.
- ArchUnit holds this: `architecture/DddLayeringRulesTest` (anchored layers, every class in a layer, context slices derived from the packages, a domain on the JDK's core only and reading no classpath resource, web-free application, controllers on no context infrastructure and no persistence port, no driven adapter on an application service, `MessageSource` only in adapters, `shared_kernel_must_not_depend_on_any_context`; each rule has a planted violation it must report), `FrameworkBindingRulesTest` (configuration binding and start-up triggers only in adapters) and `AdapterLibraryRulesTest` (each third-party library confined to its adapter). A new context needs no rule change, only its `includeAll` line in the master changelog; a new library gets its confinement rule.
- `architecture/StereotypeRulesTest` keeps each stereotype in its layer (meta-annotations included): controllers (named `…Controller`) and problem handlers in `interfaces/rest`, `@Service` in `application`, `@Repository`, `@Configuration` and `@Scheduled` in `infrastructure` (`@Configuration` also in `interfaces/rest`), no `@Transactional` in `interfaces` or `domain`, no injected field or setter, records for `@ConfigurationProperties`, requests, responses, request bodies and events, the SLF4J field `private static final Logger log` and no other logging API, and the console only for the first setup's code; each rule has a planted class it must report.
- No package depends on itself through other packages: `architecture/PackageCycleRulesTest` makes every package of `cz.novanadeje.app` its own slice, the root and every nested package included, and refuses a cycle; when two packages need each other, choose the direction that is right and move the piece both use into a package below both.
- Name the owning context before writing code. A concept that fits two contexts means a wrong boundary or a missing context: say so, never force it.
- Cross-context only through `shared`: an event record in `shared/application/event/` published with `ApplicationEventPublisher` and consumed with `@TransactionalEventListener` (`BEFORE_COMMIT` for a copy that must not be lost, `AFTER_COMMIT` + `@Async` for side effects like mail; a plain `@EventListener` only in `MailDeliveryListener` and `SecondFactorRecoveryPaymentListener`, each named with its reason in `architecture/EventListenerRulesTest`) by a consumer in the consuming context's `infrastructure` (usually `<context>/infrastructure/events/`, `DonorRecordSynchronizer`), which either does its technology's work itself (the mail senders, `LiveHintListener`, `AdminActionLog`) or calls an application service with the event's values (ids, instants, kinds), never the event itself; the phase, `@Async` and the plain listener sit on the adapter, and the service keeps its logic and transactions (`EventListenerRulesTest`: `shared_events_are_consumed_by_infrastructure_adapters`, `application_code_takes_no_shared_event` for every public application method and constructor, a functional interface of a shared event it returns included, `application_values_hold_no_shared_event` for every application field javac did not generate, and `shared_events_are_heard_only_through_annotated_listeners`, which refuses every listener registered in code, of any event: an `ApplicationListener` bean, `forPayload` or a listener handed to the context; a shared event is a top-level record of that package, and a kind nested in one, such as `StoredDataChanged.LiveFeed` or `ImportOutageChanged.Change`, is a value (a live feed only as a constant of `<context>/infrastructure/events/<Context>LiveFeeds`, one audience per wire name, `architecture/LiveFeedRulesTest`), and a listener of `Object`, `Record`, `ApplicationEvent` or any payload hears every shared event unless its annotation names its events), or, for a read the consuming context cannot own, a port in `shared/application/<topic>/`, implemented in `shared/infrastructure/` when shared owns the data or library (`AdminActionTrail`) or by the owning context's infrastructure (`AlertRecipients`); name a new port in the PR. A context keeps its own copy of foreign data (`donor_record` in donations). Events used inside one context live in `<context>/application/event/`, and a listener of a context's own event may stay in application (`PushAlertDispatcher` on `OperationalAlertChanged`).
- `shared` holds only stable concepts: value objects that at least two contexts use, or one context and shared's infrastructure (`Money`, `EmailAddress`, `VariableSymbol`, the donor's `DonorName` and `CompanyIdentifier`, …; `architecture/SharedKernelRulesTest`, whose reviewed list names any that serves one context by design, empty today, so a value of one context such as `Iban` lives in that context), the `UuidV7` generator, the `Sha256` digest (the only caller of `MessageDigest.getInstance`, `architecture/DigestRulesTest`), the sealed `DomainException` family, the cross-context events and ports, and cross-cutting infrastructure (security, problem handling, rate limiting, clock, scheduling, async, branded e-mail, the audit log, `BuildRevision`).

## Domain
- Aggregates own their invariants and behaviour (no anemic entities); value objects are records that validate in the compact constructor, and a record of a domain or application package that holds an array copies it in and out and declares its own `equals` and `hashCode` by content and a `toString` without the bytes (`architecture/ArrayRecordRulesTest`); ids are records over `UUID`, generated by `UuidV7`, and an entity of another context is held as this context's own reference record of the same shape (`DonorReference`), never as the other context's id type; no supertype's type argument, type parameter's bound, field, record component, parameter or return type of a domain class is a raw `UUID`, inside a generic type, optional or array either, except the `value` of an id record itself (a record named `…Id` or `…Reference` whose only component is `UUID value`; its other members are checked) and the declarations `architecture/DomainIdRulesTest` lists one by one with their reasons (the `UuidV7` generator; #980 and #981 empty the rest, and a test fails on a listed declaration that is gone), and application services and adapters convert at the boundary (a controller from the path, a persistence adapter to and from the column). Domain services only for rules spanning aggregates (`PaymentPairingPolicy`, `AdministratorRoster`), over data the application service loaded under its locks.
- Failures are named classes with a `code`, declared in a domain package, of the sealed `DomainException`'s abstract kinds: `RuleViolation` 400, `Conflict` 409, `NotFound` 404, `AuthenticationFailure` 401, `AccessDenied` 403. A kind's constructor is protected, so a failure is never thrown as a bare kind, and `architecture/DomainFailureRulesTest` refuses an anonymous or local one. `ApiExceptionHandler` maps them to problem+json with `problem.<code>.title|detail` from `i18n/messages_{cs,en}.properties`; add both texts with the exception. A code is one constant of lowercase words, digits and dashes joined by slashes, held by the failure class itself (`ProblemTextsTest`, which also refuses a text in any bundle that no code, handler or `ErrorResponseException` reads). A failure carries domain values and plain data (a version, an id), never a field or parameter typed `Object`, `Record` or `Serializable`, nor one of the site's own types that reaches one through its fields (inherited ones included) or has an implementation outside a domain package (`DomainFailureRulesTest`; an `equals(Object)` override aside), through which an application view would reach the problem body unseen by the layering rules; a stale write's conflict extends `shared/domain/error/StaleWrite` and the record as stored now travels beside it in `shared/application/version/StaleWriteRefusal` as a `StoredRecord`, which only records of an application package implement, holding only plain values (primitives and their boxes, strings, `BigDecimal`, `BigInteger`, the value types of `java.time`, `UUID`, `Optional`, `Locale`, `Currency` and the collections and maps of `java.util`, never raw; no `Object` or `Throwable`), enums of the site and other such application records, generic ones included (never an aggregate or a domain record), and a stale write whose constructor names a version (its `super` call does, through a factory too) is built only in the method that builds its `StaleWriteRefusal` (`DomainFailureRulesTest`); `ApiExceptionHandler` answers it with `current`.
- No class extends `IllegalArgumentException`, which the API answers 400 as the client's error, or `IllegalStateException`, which adapters catch generically around library calls (`architecture/DomainFailureRulesTest`); a failure of the code's own is a `DomainException` when the client caused it, and when the server did a named `RuntimeException` subclass (`InvalidReceiptProof`, `BankStatementUnavailable`) or, for a broken invariant of the server's own data or code (a link of another donor reaching a repository), a plain `IllegalStateException`, never a subclass of it and never thrown inside an adapter's `try` that catches it around a library call, where it would pass for undecodable input; both answer 500. A persistence adapter (a class of the packages `AdapterLibraryRulesTest.PERSISTENCE_ADAPTERS` confines JPA and Spring Data to, configuration records aside, or a `@Repository` wherever it lives) constructs no `IllegalArgumentException`, a lambda's included, and calls no `Assert` method but `state` (`DomainFailureRulesTest`, `persistence_adapters_never_answer_a_broken_invariant_as_the_clients_error`), because a client's input is refused before it reaches persistence; the rule does not see one another call throws (`valueOf`, `fromString`, a value object's check; #939).
- `Clock` is injected, never `Instant.now()` (`architecture/TimeRulesTest` refuses every read of the system clock, a method reference included: a `now` of `java.time` without a `Clock`, a system `Clock` or `InstantSource` outside `ClockConfiguration`, `System.currentTimeMillis()`, a new `Date` or `Calendar` without arguments, `Calendar.getInstance`; `UuidV7.generate` takes the instant). The foundation's calendar is Prague's: the zone is `shared/domain/FoundationZone` (`ID` for `@Scheduled(zone = …)`, `ZONE`), never a `"Europe/Prague"` literal in the main Java sources (`TimeRulesTest`); donations' dates go through `FoundationCalendar`, `ReceiptCalendar` and `BankCalendar`.
- A case change or a format names its locale (`toLowerCase(Locale.ROOT)`, `String.format(Locale.ROOT, …)`, a reader's locale for a text people read), because the default one changes the result (a Turkish locale lowers `I` to `ı`, `ar-EG` writes `%d` in Arabic-Indic digits, which would break a TOTP code, an IBAN's check digits or a receipt number) and the production JVM's default comes from the base image's `LANG`, which the project does not own. `architecture/LocaleRulesTest` refuses, without a `Locale` (or the `DecimalFormatSymbols` or `DateFormatSymbols` of one): `String.toLowerCase()` and `toUpperCase()`; `String.format`, `String.formatted`, a new `Formatter`, `printf` and `format` of a `PrintStream`, `PrintWriter` or `Console` and a `Console` prompt, and `MessageFormat`'s constructor and static `format`; the `NumberFormat`, `DecimalFormat` and `DecimalFormatSymbols` factories and constructors (a `ChoiceFormat` and a subclass's own `super()` aside); `DateTimeFormatter.ofPattern` and `ofLocalized…` (a localized style is `new DateTimeFormatterBuilder().appendLocalized(style, null).toFormatter(locale)`), `DateTimeFormatterBuilder.toFormatter`, and the `DateFormat`, `SimpleDateFormat` and `DateFormatSymbols` factories and constructors (a pattern of digits only would be safe, but the rule cannot see the pattern); and it refuses `Locale.getDefault`, `Locale.setDefault` and a `Collator` or `BreakIterator` made without a locale, so no format names the machine's locale in name only. Tests run code under such a locale with `support/ArabicDigitsDefaultLocale`, which restores every locale category afterwards.
- `Optional` for return values and for record components that may be absent; never `null` for absence across a method or constructor boundary, never an `Optional` field in a class (`architecture/OptionalFieldRulesTest` refuses one, an `OptionalInt`, `-Long` or `-Double` or an array of one, in every class that is not a record and in a record's static fields; a cache or map that remembers a known absence as an `Optional` value is not such a field; inside a class, a private nullable field read only through an `Optional` accessor), no new `Optional` parameters. Immutable by default.

## Application
- One application service per use case, or per tightly related group of use cases on one aggregate (`NewsAdminService`); never a service spanning unrelated aggregates. Commands, queries and views are records; the layer knows no HTTP, JPA entity or template. Ports are interfaces here, implemented in infrastructure; an adapter translates its technology's failures and handles (a lost race, a file) into the port's own types. A driven adapter (one that implements a port of its own context's `application` or `domain`, an interface or an abstract class, or a `shared` port its own context's `application` or `domain` uses) builds on the domain and its technology and never calls an application service, directly or through an infrastructure class of its context, which would turn the hexagon round (`DddLayeringRulesTest`, `driven_adapters_must_not_drive_a_use_case`); a use case is driven only from the driving side: a controller, a scheduler (`FioImportScheduler` also takes `BankImportRequests`, which only queue a run on its thread, the rule's one named exception; a scheduled method does not exempt a class), a listener, or another context through a `shared` port, whose adapter in the owning context is that context's driving side (`FreshSecondFactorAdapter`). A failure only the driving side can see (the commit of a `REQUIRES_NEW` call) is caught there (`DonorRecordSynchronizer`). Only a persistence adapter uses a port that a persistence adapter implements (one of the packages `AdapterLibraryRulesTest.persistenceAdapters()` names, the audit trail's included): any other adapter, the adapter of a `shared` port too, gets what it needs from the database from an application service, which reads it inside its transaction and hands it over, as `ImportAlertDelivery` hands `ImportAlertSender` the recipients (`DddLayeringRulesTest`, `only_persistence_adapters_use_persistence_ports`). Its list of readers is a debt #959 empties, not a kind of exception: no new entry, and a test fails once a listed reader no longer needs it. `architecture/ApplicationLayerRulesTest` refuses in `..application..` Spring's `dao`, `jdbc`, `orm`, `data` and `mail`, JPA, Hibernate, `java.sql`, `java.nio.file`, Jakarta Mail, Thymeleaf and `TransactionSynchronization*` (after-commit work goes through a port such as `AfterCommitWork`; `TransactionOperations` stays allowed), with no exception. No method of an application or domain class (static or instance, of any class but a repository) and no constructor there but a Spring component's (`@Service`, `@Component`: constructor injection; a record is never exempt) takes a repository, alone or inside any generic type, bound, array or varargs (a type of the site named `…Repository` or implementing one, or a port a persistence adapter implements, one annotated `@Repository` or built on Spring Data, JPA or JDBC, such as `PairingLock` or `AdminActionTrail`; a domain class is never a component, so a domain service takes loaded data and never holds a repository; `application_and_domain_code_takes_no_repository_parameter` in the same test), because it hides a dependency and keeps a rule outside the aggregate or a domain service: a rule over loaded data goes to the domain or the view with the read in the service, a read or write to an injected collaborator (`ReceiptCoverage`, `BankLogoImageChanges`, `ProjectViews`).
- A value of a business rule (a lifetime, a limit, a set of kinds) lives in the domain, and an adapter or REST class gets it from the event, command or result of the use case, never by reading, writing or getting a static value of an application class (an enum constant, `values()` and a factory of the class's own type aside; `architecture/ApplicationValueRulesTest`). javac copies a compile-time constant, a `String` or a primitive, into the reader, which the rule cannot see yet (#961): the lifetime of an unconfirmed registration is `donors/domain/UnconfirmedRegistration`, which the expiry's `ExpiredRegistrations` and the reminder event `DonorRegistrationReminderDue` carry to the scheduler and the mail adapter (#952).
- `@Transactional` on application services (`readOnly` for queries), never on controllers; an adapter's `@Transactional` only joins the use case's transaction (`Propagation.MANDATORY`, `architecture/TransactionRulesTest`, which checks the declared ones, not the transactions Spring Data's inherited `save` and `delete` open by themselves), and only Spring's `@Transactional` is used; short transactions. A use case that calls the network, decodes images or compares a password keeps that work outside the transaction and writes through a short transactional collaborator (`BankStatementRecorder`) or a `TransactionTemplate` (`UploadImageService`); its public method has no `@Transactional`. `architecture/PasswordHashingRulesTest` refuses a call or reference to `PasswordHasher` or `DonorConfirmations.confirm` in a `@Transactional` method or class, in a lambda of a method that runs a `TransactionOperations` or `CommittedRefusals` (so the hash before the transaction goes outside any lambda there), and in the application methods any of these call.
- Deliberate exceptions, each explained in `docs/system-overview.md`: receipt issuance freezes and signs under the donor lock, including the signatory's print portrait (`FoundationPeople.printPortraitOf`, also read inside `ReceiptSignatoryService`'s transactions); the monthly report sends inside its transaction, so a refused send leaves the month unsent.
- `REQUIRES_NEW` only where a separate transaction is the point: `DonationReceiptIssuer` (one transaction per issue), pairing called from an `AFTER_COMMIT` listener (`PaymentPairingService.pairPaymentsOf`, whose caller opens no transaction), the monthly report's figures (`MonthlyReportFigures`, a read-only `REPEATABLE READ` snapshot inside the `READ COMMITTED` sending transaction), the mail outage (`MailWatch`, so a refused send inside the monthly report's transaction, which rolls back, still opens the alert) and the audit of a refused backup key reveal (`BackupKeyRevealRefusals.record`, so the refusal stays whatever the reveal's transaction does). Each one is one more connection (`database.md`), and `architecture/TransactionRulesTest` refuses any other, by annotation or in code (`Propagation.REQUIRES_NEW`, `setPropagationBehavior`, a `DefaultTransactionDefinition` with a propagation); only the application opens a transaction in code (`TransactionTemplate`, `TransactionOperations`, `PlatformTransactionManager`).
- Retry-safe by design (`reliability.md`).

## REST (`<context>/interfaces/rest`)
- Paths `/api/<context>/...`; the administration under `/api/admin/<context>/...` (role `ADMIN`, `security.md`). Request and response records only (`architecture/ResponseRecordRulesTest`: a handler answers with a `…Response` of `interfaces/rest`, nothing, bytes, a text, a resource or an event stream, and a response holds only types of `interfaces/rest`, JDK types and enums); Jakarta validation on requests with `@Size` limits from domain constants; `Accept-Language` selects texts.
- Errors are problem+json: types `https://nfnn.cz/problems/<context>/<code>` (`ProblemTypes`); validation 400 with `errors[{field,message}]`; 401/403 from the security chain (never a Basic challenge); 429 `rate-limited` from a limiter built like `SignInRateLimiter` (per client address, counted before any hashing or work). A failure outside the `DomainException` kinds (an upstream 502) gets a handler in the context's `interfaces/rest` (`AdminReportProblemHandler`).
- A public endpoint needs its `permitAll` line in `ApiSecurityConfiguration`; everything else needs the donor JWT. Another donor's resource answers 404.
- Every endpoint change updates `docs/api-contract.md` in the same PR.

## API versions and compatibility (plan v3 2.3)
- Every `/api` answer names the server's build (`Nfnn-Revision`) and API generation (`Nfnn-Api`); the app names its own (`Nfnn-App`, `Nfnn-App-Api`); the server answers a write from another generation with 426 `app/update-required`, and the app holds its writes and loads the new version by itself at the first free moment (`docs/system-overview.md`, shared and Frontend).
- Expand and contract: a new field, endpoint, table or meaning comes first, in a release the previous app and image keep working with; a field, endpoint, column or meaning is removed or changed only in a release after the last app, connector tool and image that used it are gone, never in the PR that stops using it (the schema half is Persistence below). A tab opened before a deploy is such an app, so "no longer used by the code on `main`" is not enough.
- A breaking API change (a removed or renamed field or endpoint the previous app calls, a changed meaning, a newly required request field, a new value in a closed list it switches on: an enum, a status word, a problem code it handles) and every contract step (nothing tells when the last tab of an older release is gone) bumps the generation in `VersionHeadersFilter.API_GENERATION`, `frontend/src/app/core/version/api-generation.ts` and `api-generation.json` together (`ApiGenerationTest`, `api-generation.spec.ts`) and names the break in the PR. A generation never goes back to a number it had. Prefer expand and contract, and bump on the contract step.
- Until the first real receipt (January 2027, plan v3 A2) a breaking step may skip expand and contract when its PR names it, but it still bumps the generation; from then on the whole rule holds, and the receipt path changes only by additions until 4 May 2027.

## Persistence
- Before changing the schema, a query, a lock, a transaction's isolation or the datasource, read `database.md` (it loads by itself only when such a file is opened).
- JPA entities and Spring Data repositories are package-private details of `<context>/infrastructure/persistence/` (the audit log in `shared/infrastructure/audit/`), behind the adapter that implements the domain repository and maps domain ↔ entity (ArchUnit); a test outside the package reads tables through `JdbcClient`.
- Liquibase: `db/changelog/<context>/NNN_<change>.xml` (next free number in that folder), changesets `id="NNN-<kebab-case>" author="nfnn"`, auto-included by the master. One file per logical change; a changeset touches only its own context's tables. Never edit, rename or move a file that is on `main` (its identity is id + author + path): fix forward with a new one.
- The previous image keeps working against the new schema, because a rollback is the older image (`reliability.md`). Safe: new tables, nullable columns, columns with a default that stays, wider types. Breaking: a new `NOT NULL` without a lasting default (add, fill and constrain in one changeset breaks an older image that inserts into the table), a dropped default, a new or narrowed `check`, unique or foreign-key constraint the older code can violate, a narrowed type, a rename or a drop. A breaking step lands one release after the code stops depending on it, named in the PR.
- Every changelog after the deployed revision runs over data (`MigrationOverDataTest`, which fails on a baseline table without a row, a baseline file out of master order, and a baseline revision (`BASELINE_REVISION`) other than `.github/deployed-revision`): the PR that sets `.github/deployed-revision` moves the baseline with it, to every changelog `git ls-tree -r --name-only <revision> backend/src/main/resources/db/changelog/` lists in `src/test/resources/migrations/baseline-changelog.xml`, in master order, with a row in `baseline-data.sql` for each new table and the new columns filled. A changeset that deletes rows on purpose names each table as a `ReviewedRowLoss`; once it is deployed, the baseline moves past it and retires the allowance, and a later changeset of its context waits for that.
- `admin_action` is append-only in the database: only a changeset (under Liquibase's lock) may rewrite the trail, and a test empties it only through `DatabaseCleaner` (`database.md`, Schema and migrations).
- Constraints state invariants (unique, partial unique, `check`). Index every query path that grows with the data; every foreign key leads a non-partial index (`ForeignKeyIndexTest`), so deleting a parent or reading its children never scans the child table. Types: `uuid` ids, `timestamp with time zone`, `date`, `varchar(n)` sized to the domain limit, `text` for long text, `bigint` amounts in minor units, `bytea` for binary content, singleton tables with `smallint id check (id = 1)`.
- `open-in-view: false`: load what the use case needs inside it; no lazy access afterwards.

## Configuration and operations
- `@ConfigurationProperties` records under `app.*`, validated at startup (fail fast: `JWT_SECRET` outside dev, invalid IBAN, empty optional values), live in infrastructure. A record the application needs is a plain record there, validated in its constructor, which the context's `infrastructure/config/<Context>ApplicationProperties` binds as a nested group (`@DefaultValue`, so a missing group still fails) and `<Context>ApplicationConfiguration` hands to the application as a bean; `StartupBindingSettingsValidator` checks stored settings against these bindings too. Reacting to the start is a driving adapter as well: an `ApplicationReadyEvent` listener lives in `<context>/infrastructure/startup` and calls an application method (`architecture/FrameworkBindingRulesTest`: no `org.springframework.boot`, framework lifecycle event or `Lifecycle` in application or domain). Production defaults in `application.yml`, dev overlay in `application-dev.yml`, local env names in `.env.example`. A value the server's operator must set is an `operations` `Setting` (first setup or `/sprava/nastaveni`, loaded under its env name by `DatabaseSettingsEnvironmentPostProcessor` in `prod`) with a label in `frontend/src/app/features/operations/setting-labels.ts`, never an env file line. Without `FIO_TOKEN` the import is off (`DisabledFioClient`, no scheduler bean). `architecture/RuntimeConventionRulesTest` holds the runtime conventions: ids only from `UuidV7`, configuration only from bound records (no `System.getenv`, system property, `Integer.getInteger` and its siblings or `@Value`, and the Spring `Environment` read only by adapters), the JVM exited only by `ExitingApplicationRestarter`, every Caffeine cache with a maximum size or weight on its builder (never `Caffeine.from` a specification), every `HttpClient` with a connect timeout and `Redirect.NEVER` (never `HttpClient.newHttpClient()`), and every `HttpRequest` with its timeout.
- Threads are an adapter's concern: an application or domain class uses no `Executor` (nor any subtype), `Executors`, `ThreadFactory`, `Thread.Builder`, `TaskScheduler`, `Timer`, `Semaphore`, `LockSupport` or `@Qualifier`, creates no thread (`new Thread`, a subclass, `Thread::new`, `Thread.ofVirtual`, `ofPlatform`, `startVirtualThread`), sleeps on no thread (`Thread.sleep`, `TimeUnit.sleep`) and calls no `parallelStream`, `BaseStream.parallel`, `Arrays.parallel…`, `ForkJoinTask.fork`/`invoke`/`invokeAll` or `CompletionStage` method ending in `Async` (`architecture/ConcurrencyRulesTest`; a `StreamSupport.stream(…, true)` it cannot see); fan-out, a cap, pacing and the executor a task runs on sit behind a port (`PushDelivery` with its `PushPace`, `PushRetryTimer`).
- Scheduled work shares one thread: every cron job has a property that `-` turns off (tests pin them off, `CLAUDE.md` Gotchas), catches its own exceptions, logs the outcome and tolerates a missed run; one-off timers (import follow-ups, log-level resets) run on the same thread, so nothing on it may block beyond its call's timeout.
- Logging: SLF4J `log` field; content as `security.md` Logs; `warn` for expected failures; `error` with the stack trace only for unexpected failures whose message cannot carry personal data; mail and SQL failures log the id and the exception class. An exception's message names the field and the rule, never the refused value, and the application reads no exception's message (`ApplicationLayerRulesTest`): an adapter hands it a closed value of its port (`docs/security-overview.md`, Logs). An `@Async` listener catches its own exceptions; one that escapes reaches `shared/infrastructure/async/ClassOnlyAsyncExceptionHandler`, which logs the method and the exception's class only.
- E-mails are Thymeleaf fragments (`th:fragment="content"`) in `templates/email/<context>/` inside the shared `templates/email/layout.html`, composed by `BrandedEmails` from an `EmailDraft`: text and HTML parts, `th:text` only, inline styles with theme colours only, sender `app.mail.sender-email`, links from `app.site.public-url`. There is no receipt template: the browser draws the receipt (skill `receipt-template`).
