# Frontend rules: Angular, UI, UX

## Angular 22 (standalone, zoneless, signals)
- Components: flat names `hero.ts/.html/.scss`, class `Hero` (no `Component` suffix), selector `app-*`, no `standalone: true` (default), no NgModules. Change detection is OnPush (Angular 22's default; the existing components still spell it out, a new one may omit it); never `ChangeDetectionStrategy.Eager`/`Default` (lint rejects it). So a template may read only signals, inputs and what its own events change: state that arrives otherwise (the forms API, a subscription) goes through a signal, as `appFormControl` turns the control's events into `showsError()` and `errorKey()`.
- State in `signal`/`computed`/`linkedSignal`; `input()`, `output()`, `model()` instead of decorators; `inject()` instead of constructor parameters; a parameterless constructor holds the start-up work (initial load, `effect`, `afterNextRender`, `DestroyRef.onDestroy`); `host: {}` metadata instead of `@HostListener`/`@HostBinding` (lint: `prefer-host-metadata-property`); no `any`; strict TS and templates stay on.
- Templates: `@if/@for/@switch/@defer`; `[class.x]`/`[style.x]` (no `ngClass`/`ngStyle`); import only the directives and pipes used (never `CommonModule`); logic in the class.
- Forms: template-driven `ngModel` inside `<app-form-field label hint [messages]>` with `appFormControl` (needs `id` + `ngModel`) and `form[appFocusFirstInvalid]`; the field shows its own first error after touch or submit (`aria-invalid`, `aria-describedby`), and a field left by a pointer press shows it only when the press ends, so the message cannot move the button away from under the pointer; a form-level alert only for what no field owns (passwords differ, an API refusal). Signal Forms are stable in Angular 22 but not used here: switching means migrating `form-field`, `appFormControl` and every form at once, so only by decision.
- Local first (`backend.md`): compute and render here whatever the data already in the browser allows; the backend only serves it.
- HTTP and data: one `providedIn: 'root'` service per backend resource, `<name>-api.ts` in its feature folder (sign-in and account calls: `core/auth/auth-api.ts`), relative `/api/...` only, DTO interfaces mirroring `docs/api-contract.md`; a component calls it and `subscribe`s into signals, as every existing page does (no `httpResource`/`rxResource` piecemeal). Every call passes `authInterceptor` (Bearer header, problem+json Blob parsing, one refresh on `auth/expired-token`) and then `versionInterceptor` (`core/version/`: the app's `Nfnn-App` and `Nfnn-App-Api` on every `/api` call, the server's `Nfnn-Revision` and `Nfnn-Api` read from every `no-store` answer into `ServerVersion`, and while the server speaks another API generation every write but the session refresh, sign-out and receipt status answered locally with the problem `app/update-required`, which the server also answers to a write from another generation; a page that keeps its own failure text recognises the problem, as the contact form and the receipt download do); only the API service of a public endpoint may send its request without the token, with the context `WITHOUT_ACCESS_TOKEN` (`core/auth/auth-interceptor.ts`), and ESLint's `no-restricted-imports` in `eslint.config.js` allows that import only in the files listed there (today `payment-details-api.ts`, the receipt verification's `receipt-keys-api.ts` and `receipt-status-api.ts`, and `setup-api.ts` for the setup status the restart wait polls): a new public endpoint that should skip the token adds its service to that list; errors become one line through `describeProblem` (`core/auth/api-problem.ts`). The live stream (`core/live/live-api.ts`, `GET /api/live`) is an `HttpClient` call too, a text stream read through download progress, so it carries the token and refreshes like any call; a page listens through `LiveUpdates.changes(feeds)` and keeps working when no stream is open. Three calls bypass it with a raw `fetch`: `core/errors/error-reporter.ts`, whose browser error report goes with `keepalive` and `credentials: 'omit'`, so it never carries a token, survives the page closing and cannot itself fail through the interceptor into another report; `core/reload/chunk-probe.ts`, whose `HEAD` asks the server for a lost chunk (`cache: 'no-store'`, aborted after 4 s) and is no API call; and `receipt-pdf/receipt-fonts.ts` in the receipt PDF worker, which reads the theme's TrueType files from `/receipt-fonts/` (static files of the build, no API call; a worker has no `HttpClient`). Nothing else calls `fetch`. The HTTP backend is XMLHttpRequest (`withXhr()` in `appHttpClient`, `app.config.ts`, for the whole app): fetch, Angular 22's default, reports no upload progress and `reportUploadProgress: true` under it throws NG02824, while the first setup's backup upload shows a progress bar (`reportUploadProgress`; `reportProgress` is deprecated since 22.0).
- Routing: lazy per feature (`<feature>.routes.ts`, `loadChildren`/`loadComponent`), `title` via `$localize`, addresses and section ids in Czech without diacritics (`/darce/prehled`, `/sprava`, `/#prispet`; only `/api/...` stays English), `/darce/**` behind `donorGuard`, `/sprava/**` behind `adminGuard`, public shell with header and footer, unknown paths show `not-found` (nginx answers 200 for every path).
- Formatting is Prettier's (`.prettierrc`: 100 columns, single quotes, Angular parser for templates): run `npm run format` before committing; CI fails on a file it would change.
- Lint is ESLint with angular-eslint (`eslint.config.js`: recommended TypeScript and template rules, template accessibility, `prefer-inject`, `prefer-signals`, `prefer-output-readonly`, `prefer-on-push-component-change-detection`, `prefer-control-flow`, `prefer-self-closing-tags`): run `npm run lint` before committing; CI fails on a finding. `eslint-confinement.js` is the frontend twin of `AdapterLibraryRulesTest`: its table `CONFINED_IMPORTS` names each library or module family with the scopes allowed to import it (`SCOPES`: `app`, `testSupport`, `routes` and the adapters; a narrower scope names the one it lies `within`, which then ignores its files, so every file is in exactly one scope whatever the order of the config objects), refuses it elsewhere statically, as a type or by `import()` of a string or template literal, refuses every `import()` of a computed name outside route files, and with `lazyOnly` allows a library in its adapter only through `import()` (types still pass). `npm run lint` also runs `scripts/eslint-confinement.test.mjs`, which lints an example of every entry in every scope and fails on a scope that matches no file; a new library or adapter adds its entry or scope and its examples there. Two scoped exceptions, both for the native `<dialog>`: `autofocus` is allowed in `*dialog*.html` because the dialog moves focus to it on open, and `shared/ui/dialog/dialog.html` closes on a backdrop click without key events because Esc closes it natively.
- Folders: `features/{content,donors,donations,contact,operations}` mirror backend contexts; `features/admin` holds every `/sprava` page whatever context it calls (a new page: `features/admin/<page>/`, calls in `admin-api.ts` unless the context already has a feature service for both sides, as content's `news-api.ts` and `projects-api.ts`, a route in `admin.routes.ts`, an entry in `ADMIN_SECTIONS`); singletons in `core/`; a behaviour-only piece used twice moves to `shared/ui/` (`form-field`, `dialog`, `copy-button`, `share-button` for the Web Share API with the copy button as its fallback, `password-reveal`, `qr-code`, `avatar` for a person's round portrait or initials, `markdown` for content bodies, `side-nav` for the side panel of `/sprava` and `/darce`, `account-username` for the hidden user name of a form that asks for the current password).
- Trusted Types are enforced (`security.md`, Browser): no string reaches a markup, script or script-address sink (`innerHTML`, `insertAdjacentHTML`, `DOMParser`, `script.src`, `importScripts`, `eval`); text goes in through bindings or `textContent`, a worker starts only as `new Worker(new URL('./x.worker', import.meta.url), { type: 'module' })`, which the build turns into `/worker-<hash>.js` and the site's `default` policy (`core/security/trusted-types.ts`, installed in `main.ts`) admits, and a new library is checked for sinks under the e2e suite before it lands.
- No CDN, inline script or third-party resource (CSP rule in `security.md`): fonts, images and scripts come from `public/` or the build, and QR codes are inline SVG drawn by `shared/ui/qr-code` from the module matrix (the saved PNG goes through a `data:` image and a canvas), which the browser encodes itself with `qr-encoder.ts` (no library; the authenticator QR since 1.3, the payment QR from 1.4).
- Receipt PDF: drawn in the browser by `features/donations/receipt-pdf/` in a module worker (`receipt-pdf.worker.ts`, its own chunk); pdfkit only in `receipt-layout.ts`, and that file only in the worker and tests (`eslint-confinement.js`), so no other bundle carries it; the layout takes its colours, type sizes, leading and margins from `ReceiptStyle` and its fonts from the theme (it owns only the geometry of its blocks, as a component owns its structure), and every word from the frozen receipt or the captions passed in.
- Receipt verification (`/overit`, `features/donations/verification/`, `docs/frontend-overview.md`): the proof is read and checked in the browser, with WebCrypto `Ed25519` and, only where the browser lacks it, `@noble/curves` from `noble-ed25519.ts` through `import()` (a lazy chunk); the key list kept in `localStorage` is replaced whole by each trusted list, never merged; a code is read from the browser's `BarcodeDetector` or else jsQR, which only `qr-decoding.ts` imports and only the module worker `qr-decoder.worker.ts` loads (`eslint-confinement.js`), so it is in no page bundle; the camera (`Permissions-Policy camera=(self)`) starts only on the visitor's press and stops on a read, on stop, after two minutes and when the tab is hidden or the page is left; only the exact prefix `https://nfnn.cz/overit#` with digits is accepted, and nothing read is ever opened or navigated to.
- Device copies (`core/device/crypto/`, plan v3 2.13, `docs/security-overview.md` "Device copies"): only WebCrypto and the Argon2id worker; every key imported or generated is non-extractable, the root key lives only in an open `OpenCopy` and is zeroed by `close()`; every record and wrap is sealed with AES-GCM and the length-prefixed additional data of `framed`, so a new kind of record or wrap names its own label and fields there; hash-wasm only in `argon2.ts`, which only `argon2.worker.ts` loads (`eslint-confinement.js`), and the app derives a password key only through `WorkerPasswordKeyDerivation` with its parameters stored beside the wrap; no e-mail, name or user handle in the clear outside an open copy (the registry keeps tags); the core stores nothing itself (lint refuses it every browser store, `scripts/device-crypto-storage.test.mjs`); the PRF input is per device, never per copy, so one passkey ceremony opens every copy; a PRF output never leaves the device, so `PasskeyAuthenticator` keeps sending no `clientExtensionResults`.
- Sessions: access token in memory (`AuthStore`; after a refresh posted to the other tabs over the `BroadcastChannel` `nfnn-session`, never stored), refresh cookie set by the browser, `localStorage` flag `nfnn.donor-session` only says a session may exist; nothing else adds auth headers.

## i18n
- Czech source: every visible string has `i18n="@@<area>.<page>.<key>"`, the first segment one of `home`, `content`, `donor`, `admin`, `operations`, `layout`, `ui` (follow the neighbouring component); attributes `i18n-alt`, `i18n-aria-label`, `i18n-placeholder`; TS text with `$localize\`:@@id:text\``. Ids are stable, never renamed. There is no translation file yet.
- The source locale is `cs` (`angular.json` `i18n.sourceLocale`, so the build carries the Czech locale data and `LOCALE_ID` is `cs`; specs get the same from `src/test-providers.ts`). Format through the cs-CZ helpers, one place per format, not Angular's locale pipes: `formatMinorUnits`/`formatCrowns` (`donation-amount.ts`), `formatDonationDate`/`formatBankTime` (`donation-date.ts`), `formatMonth`/`formatMonthRange` (`donation-month.ts`), `formatReportMonth` (`admin/report/report-month.ts`); ICU plurals use the Czech categories `one`, `few` and `other` (`=0` only for a sentence of its own); TypeScript picks a form with `pluralCategory(count)` (`core/i18n/plural-category.ts`, over `Intl.PluralRules('cs')`).
- Czech copy: no vocative or declension of names (show the name alone); sentence case; the donate action is "Přispět"; amounts from the API (hellers) go through `formatMinorUnits(minor)` (crowns typed by a visitor through `formatCrowns`), which gives `1 000` or `1 000,50`, followed by `&nbsp;Kč` in a template and `\u00a0Kč` in TS; dates `15. 03. 2026`; bank times in Prague time; backend titles and details are shown as they come (already localized).

## UI (the look)
- The look is a swappable theme, independent of behaviour (Jakub 2026-10-23, plan `/mnt/project-files/nfnn-ux/oddeleni-vzhledu.md`). The theme owns every value of the look; a component owns only its structure (which grid, flex or order, which widths of its own content, which token for which part). Replacing the theme must restyle the whole site without touching a template, a component's SCSS or any TypeScript.
- A theme is a folder `src/themes/<name>/` with `_theme.scss` (its `@font-face` rules and every token on `:root`, plus at most rules that restyle the `ui-` blocks), its fonts, `assets/` (the files of its look, served at the site root by its build configuration with `output: "/"`: the tab icons `favicon.svg` and `favicon.ico`, `apple-touch-icon.png`, `app-icon.svg`, `images/logo.svg` and `images/logo-on-dark.svg`; every theme carries the same file names and none of them is also in `public/`) and `receipt/` (the receipt PDF's TrueType fonts `body.<hash>.ttf`, `body-bold.<hash>.ttf` and `heading.<hash>.ttf` with their licence, made by `scripts/make-receipt-fonts.sh`, which also writes their names into the theme's `--receipt-font-*` tokens; `angular.json` copies them to `/receipt-fonts/`, the control theme's under its configuration; the `--receipt-color-*` tokens are literal `#rrggbb`); `styles.scss` loads it as `@use 'theme'` from the include path, so the build picks the theme: `nova-nadeje` by default, `control` with the configuration `control-theme` (`ng build --configuration=production,control-theme`, `ng serve --configuration=control-theme`). The control theme is deliberately different (teal, system fonts, square corners, 5 px spacing unit) and exists only to prove the swap: CI builds it and `E2E_THEME=control npx playwright test e2e/theme.spec.ts` opens every public page, the sign-in dialog, every `/darce` section and every `/sprava` page and fails on any colour or font of `nova-nadeje` that the control theme does not share. A new token goes into every theme in the same PR: `npm run lint:styles` runs `scripts/check-themes.mjs`, which fails when a theme misses a token the styles use or `nova-nadeje` sets, when a receipt colour is not a literal `#rrggbb` or its text or QR colour falls below 4.5:1 on white, and when a receipt font token names a file that is missing or whose content does not match the hash in its name, or a font sits in `receipt/` that no token names, or a `--receipt-*` token is set outside the theme's top-level `:root` block (a media query would make the receipt depend on the device), when a tab bar colour is not literal or is set anywhere but the top-level `:root` or a `@media` block of `:root`, its labels fall below 4.5:1 (the focus ring 3:1, against the bar and the pill) over a white or a black page, or a solid pill below 3:1 against a solid bar, and when the themes' `assets/` differ, shadow a file of `public/` or a build serves another theme's. A new page gets a line in `e2e/theme.spec.ts`.
- Tokens live only in the theme (`src/themes/nova-nadeje/_theme.scss`) on `:root`: colour by role (`--color-accent*`, `-text*`, `-surface*`, `-border*`, `-focus-ring`, `-danger*`, `-warning*`, `-success*`, `-on-*`), fonts (`--font-serif` Playfair, `--font-sans` Inter, `--font-mono`, `--numeric-figures`), type size in `rem` (`--text-2xs` 11 px … `--text-6xl` 44 px at the default 16 px, and fluid roles `--text-heading`, `-section-title`, `-section-title-compact`, `-cta-title`, `-article-title`, `-page-title`, `-hero`), weight (`--weight-regular` … `-extrabold`), line height (`--leading-none`, `-display`, `-heading`, `-snug`, `-normal`, `-relaxed`, `-loose`), letter spacing (`--tracking-tight`, `-slight`, `-wide`, `-widest`), spacing (`--space-<n>` = n × `--space-unit` 4 px, half steps `-0-5`, `-1-5` …, so a theme changes density with one value), shape (`--radius-*`), depth (`--shadow-*`, one per role), motion (`--duration-fast`, `-base`, `-slow`, `-entrance`), layout (`--content-max`, `--header-height`, `--floating-notice-height`, `--side-nav-layout-max`, `--side-nav-width`, `--top-bar-height`, `--dialog-max-width`, `-wide`, `--dialog-close-inset`, `-size`, `--list-row-min-height`, `--list-group-title-top`), blur (`--blur-backdrop`, `--blur-bar`), the app layout of plan v3 2.1 (the floating tab bar: `--color-tab-bar`, `-bar-rim`, `-pill`, `-active`, `--color-on-tab-bar`, `--color-tab-focus-ring`, `--shadow-tab-bar`, `--tab-bar-height`, `-gap`, `-gap-browser`, `--tab-pill-inset`, solid under `prefers-reduced-transparency`; the sheet: `--sheet-max-width`, `--radius-sheet`, `--shadow-sheet`, `--duration-sheet`, `--color-sheet-grabber`, `--sheet-grabber-width`, `-height`; no top bar, Jakub 2026-11-05), the receipt PDF (`--receipt-*`: colours, sizes in `pt`, `--receipt-leading`, margins in `mm`, read by `features/donations/receipt-pdf/receipt-style.ts`, whose list `check-themes.mjs` requires in every theme).
- Breakpoints only through `@use 'breakpoints' as bp;` (`src/styles/_breakpoints.scss`, on the include path): `@include bp.down(phone)` is `max-width`, `bp.up(cards)` is `min-width` one pixel above; names `tiny` 360, `narrow` 420, `phone` 480 (dialogs full-screen), `cards` 640 (tables as cards), `tablet` 768, `nav` 899 (side panel collapses). A new width is a new name there, never a raw `@media`, and the same name and width in `core/layout/breakpoints.ts` (`scripts/breakpoints-parity.test.mjs` fails otherwise). Code that must choose a layout asks `CompactLayout.isCompact()` (`core/layout/compact-layout.ts`, `bp.down(nav)`) and renders one layout with `@if`, never two hidden by CSS. Where a layout must give way when the visitor enlarges the text, `bp.container-down(<container>, name)` and `bp.container-up` ask a size container the same width in `rem` of the root text size: the site header (`site-nav`) and the donor's and the administration's top bar (`topbar`) switch on it alone, while the payment panel (`payment-panel`), the donor's table of gifts (`donations-table`) and the administration's months (`admin-overview`) keep their viewport query and add `container-down(…, phone)`, so at the default text size nothing changes and at a large one they stack (`e2e/devices/`). A container is a containing block for its fixed descendants, so it goes on a component's own box, never on a shell that holds a fixed bar.
- `npm run lint:styles` (in CI) rejects in components a raw colour, font, font size, weight, line height, letter spacing, radius, shadow, a `px` spacing other than a 1 px hairline (`padding`, `margin`, `gap`), a transition duration and a `width` media query. A missing value is a new token in the theme (pick the nearest existing one first; a value used once is not a reason for a token), never an inline value or a lint exception.
- Shared building blocks are global classes in `src/styles/ui/` (prefix `ui-`, BEM modifiers, loaded by `styles.scss` after the form controls): `_page` (`.ui-page`, `-head`, `-title`, `-intro`, `.ui-crumbs`), `_card` (`.ui-card`, `--danger`, `--padded` for a card whose content sits on its padding, `__title` with `--large`, `__subtitle`, `__bar` for a heading strip over a table or list, `__body`, `__intro`, `__empty`, `__footer`; `.ui-data-list` for a `dl` of label and value), `_notice` (`.ui-notice--status|--alert|--warning`, `--floating` for a bar fixed at the bottom of the screen with `__text` beside its button (the page keeps room for it through `:root.has-floating-notice` and the layout token `--floating-notice-height`, `0rem` in the theme and measured by the component that shows it), `.ui-load-state` `--error`, `--inset`, `.ui-badge--success|--warning|--accent`, `.ui-mono`, `.ui-callout--danger|--warning` for a framed message inside a card), `_button` (`.ui-button` soft accent, `--primary`, `--small`, `--quiet`, `--large` beside a primary, `--danger`, `--danger-soft`, `--danger-outline`, `--block` for a full-width form submit; `.ui-link-button`; `.ui-pill-button` with `--done`, the small outlined pill of `copy-button` and `share-button`), `_table` (`.ui-table`, cards at `bp.down(cards)`), `_form` (`.ui-field-error` under a form, `.ui-segmented` choice of two or three buttons with `.is-active`, `.ui-form-status` for the saved line after a form), `_action-bar` (`.ui-action-bar`: the sticky bar at the bottom of the viewport that ends a long form, with `appActionBar` from `shared/ui/action-bar` so `scroll-padding-bottom` keeps the focused field above it), `_dialog` (inside `<app-dialog>`: `.ui-dialog__title` for its `h2`, `__lead` for the sentence under it, `__points` for the list of what a confirmation does), `_list` (`.ui-list` of rows `__row`, an `a` or `button`, one target per row with a second action as its own named button beside it, never inside: `__lead`, `__title`, `__meta`, `__value` with tabular figures, `__chevron` with `aria-hidden`, `__group-title` a sticky heading, `--inset` for grouped rows on a card; the compact layout's lists from 2.25), `_person-list` (`.ui-person-list` of `.ui-person-row`: `__avatar` on an `app-avatar`, `__name`, `__meta` for the line under the name, `__badges`, `__note`, `__actions` at the right and under the row up to `cards`, `__detail` across the row for an inline confirmation; the people of the foundation and the administrators), `_panel` (a standalone page such as the password reset: `.ui-panel-page` around `.ui-panel`, `__title`, `__lead`; `.ui-status` with `__icon` (`--success` green, `--caution` amber, `--danger` red for a verdict; the older `--warning` is red too, so an amber warning takes `--caution`), `--spinner` for a result or a wait), `_section` (the public site: `.ui-container` for the content width of a section, `.ui-eyebrow` above a section title with `--on-inverse` and `--accent-on-inverse` on a dark background, `.ui-intro` for the dark band that opens a page with `__title` (`--article` for a news or project title) and `__lead`, `.ui-cta` for a large call to action with `--ghost` and, on top of it, `--on-inverse` or `--on-image`). A page, card, notice, button or table uses them in its template and never copies their declarations; its SCSS keeps only layout and the rare override (a margin, a narrower width). An element keeps its own semantic class beside the `ui-` ones where specs or layout need a hook (`class="ui-button ui-button--primary profile-save"`). A look used in two features becomes a new block there, not a copy. Behaviour with a template stays an Angular component in `shared/ui/`.
- Translucency with `color-mix()`, never `rgba()`. Fonts self-hosted variable WOFF2; nothing loads from another origin.
- Tables become cards at `bp.down(cards)` (`data-label` per cell); fluid sizes are `clamp()` tokens; `prefers-reduced-motion` stops animations (global rule in `styles.scss`).
- Images: everything that can be SVG is SVG (Jakub 2026-10-30: the logo, the tab icon `favicon.svg`, icons, drawings); raster only where no SVG can do (photos, and where a platform takes only raster: `og-image.jpg`, `apple-touch-icon.png`, `favicon.ico` at the default address, unlinked, for services such as claude.ai's connector list). Photos are WebP in `public/images/` (except `og-image.jpg` for link previews); the logo, `logo.svg` and `logo-on-dark.svg` for a dark background, is a theme asset in `src/themes/<name>/assets/images/`, served at `/images/…`, and its star keeps its face, since a filter that whitens the logo would whiten the face too; photos come in sized variants with `srcset`/`sizes`, `width`/`height`, `loading="lazy"` written before `src` below the fold, `fetchpriority="high"` for the hero, decorative photos `alt=""`; icons inline SVG `aria-hidden="true" stroke="currentColor"`; no emoji in UI text.
- Budgets in `angular.json`: initial bundle warns at 500 kB, component styles at 4 kB.

## UX (how it behaves)
- Every action shows loading, success (`role="status"` line) and failure (`role="alert"` line with the backend title/detail or a Czech sentence saying what to do next); a running request disables its button and names what happens ("Připravujeme PDF…"). Put `role="status"` on an element that is always rendered and the `@if` inside it (`<p role="status">@if (msg()) {<span>{{ msg() }}</span>}</p>`, as in `passkeys-card.html`): a status element inserted together with its text is often not announced. `role="alert"` may be inserted with its text. A page's success-or-failure line is a `Notice` (`{ kind: 'status' | 'alert', text }`) shown by `<app-live-notice [notice]="…" />` (`shared/ui/live-notice`), which keeps both regions rendered; elsewhere wrap the `@if` in `<div role="status">`. A line that appears with a page or with a whole new view (the first loading line, a wizard step that takes focus) may stay inside its `@if`. A notice of the app shell that may appear on any page (`update-notice`) is an always rendered `aria-live="polite"` region without `role="status"`, so each page keeps exactly one status region. Specs read these regions as `[role="status"]:not(:empty)`, e2e as `getByRole('alert').filter({ hasText: /\S/ })`.
- Forms: visible labels, hint before error, error at the field in its own words, focus to the first invalid field, placeholders never the only label, every password field inside `<app-password-reveal>`.
- Dialogs through `<app-dialog>` on native `<dialog>` (`showModal()`: focus trapped, Esc, backdrop and × dismiss, focus returns to the opener); shared open state in a service (`LoginDialogService.open(mode, options)`); every dialog keeps a history entry through `DialogHistory`, so Back closes it (only a dialog whose opener keeps the history itself sets `[pushesHistory]="false"`: the sign-in dialog and the unsaved-changes dialog of a navigation guard); `presentation` (`auto` from the area's `DIALOG_PRESENTATION`, `centered` today, `sheet`, `full`) chooses the look below `nav`, a sheet keeps its ×. A modal dialog makes the page behind it inert, so something behind it that must be heard while it is open (the chunk-load bar) announces through `DialogAnnouncer` (`shared/ui/dialog`), whose always rendered `role="status"` region sits inside every `<app-dialog>`; e2e therefore reads a dialog's status as `getByRole('status').filter({ hasText: /\S/ })`.
- Accessibility (Jakub 2026-10-23): WCAG 2.2 AA for keyboard, screen readers, zoom and system settings, without changing the default look or behaviour; a visible change made for it needs Jakub's OK (he declined darker field borders and stopping the hero scroll dot: those change only under `prefers-contrast: more` and `prefers-reduced-motion`).
