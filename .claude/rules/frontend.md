# Frontend rules: Angular, UI, UX

What the app contains is in `docs/frontend-overview.md`; the full text of each convention below, with its lists of files, tokens and blocks, is in its section "Frontend conventions in detail". This file is what a change must keep true.

## Angular 22 (standalone, zoneless, signals)
- Components: flat names `hero.ts/.html/.scss`, class `Hero` (no `Component` suffix), selector `app-*`, no `standalone: true`, no NgModules. OnPush only (lint refuses `Eager`/`Default`), so a template reads only signals, inputs and what its own events change; state that arrives otherwise goes through a signal.
- `signal`/`computed`/`linkedSignal`; `input()`, `output()`, `model()`; `inject()`; start-up work in a parameterless constructor; `host: {}` instead of `@HostListener`/`@HostBinding`; no `any`; strict TS and templates stay on. Templates: `@if/@for/@switch/@defer`, `[class.x]`/`[style.x]`, import only what is used (never `CommonModule`), logic in the class. ESLint (`eslint.config.js`) holds most of this: run `npm run lint` and `npm run format` before committing; CI fails on a finding or an unformatted file.
- Forms: template-driven `ngModel` inside `<app-form-field label hint [messages]>` with `appFormControl` (needs `id` + `ngModel`) and `form[appFocusFirstInvalid]`; a field shows its own first error after touch or submit, after a pointer press only when the press ends, and a required field the visitor only passed through says nothing until submit (experts' decision for #359); every text field names its return key with `enterkeyhint`; a form-level alert only for what no field owns. Signal Forms only by decision (switching migrates every form at once).
- Local first (`backend.md`): compute and render here whatever the data already in the browser allows.
- HTTP and data: one `providedIn: 'root'` service per backend resource, `<name>-api.ts` in its feature folder, relative `/api/...` only, DTOs mirroring `docs/api-contract.md`; a component `subscribe`s into signals (no piecemeal `httpResource`/`rxResource`). The donor's gifts are read only through `DonorDonationsRepository`; every write and every other read goes to the `-api` service. Only a public endpoint's API service may skip the token, with `WITHOUT_ACCESS_TOKEN`, and only in the files `eslint.config.js` lists (a new one adds its file there). `keptPublicAnswersInterceptor` keeps only public answers that are a subset of the service worker's same-for-everyone list (its spec pins it), and a new kept path stays inside that list. A page that keeps its own failure text recognises the problem `app/update-required` (as the contact form and the receipt download do). Nothing calls `fetch` but `error-reporter.ts`, `chunk-probe.ts` and `receipt-fonts.ts`. The HTTP backend stays XMLHttpRequest (`withXhr()`), because the backup upload needs upload progress. Errors become one line through `describeProblem`.
- Own history (#431, Jakub 2026-11-06): the site keeps one browser entry and its own steps (`core/navigation/own-history.ts`), so the browser's Back leaves the site. Nothing else adds a browser entry: a full page load inside the site goes through `ExternalNavigation.loadFromServer` or `history.replaceState` + `location.reload()`, never `location.assign` or a plain `href` to a page of the site; e2e steps back with `stepBack(page)`, and `page.goBack()` is the browser leaving the site.
- Routing: lazy per feature, and only the routes marked `LOADED_AHEAD` are loaded ahead (the chunk-load journeys rely on every other page staying lazy); `title` via `$localize`; addresses and section ids in Czech without diacritics (only `/api/...` English), and a page that moves keeps its old address as a redirect; `/darce/**` behind `donorGuard`, `/sprava/**` behind `adminGuard`; an unknown slug of a detail route answers 200 and the page sets `noindex`. A new or renamed route changes its line in the map `$app_page` of `frontend/nginx.conf` in the same PR (`app.routes.spec.ts`).
- Libraries and modules are confined by `eslint-confinement.js` (`CONFINED_IMPORTS`, the twin of `AdapterLibraryRulesTest`): a new library or adapter adds its entry or scope and its examples to `scripts/eslint-confinement.test.mjs`. The only template-lint exceptions are the two for the native `<dialog>`. No `eslint-disable` directive, which is a comment: ESLint runs with `noInlineConfig` and `ng lint` fails on a warning (`maxWarnings: 0`); an exception is a scoped config object or a named helper in a file the rule ignores (`e2e/fixed-waits.ts`, `testing.md`, Frontend e2e).
- Folders: `features/<context>` mirror the backend contexts; every `/sprava` page lives in `features/admin/<page>/` (calls in `admin-api.ts` unless the context has a service for both sides, a route in `admin.routes.ts`, an entry in `ADMIN_SECTIONS`); singletons in `core/`; a behaviour-only piece used twice moves to `shared/ui/`.
- Trusted Types are enforced (`security.md`, Browser): no string reaches a markup, script or script-address sink; text goes in through bindings or `textContent`; a worker starts only as `new Worker(new URL('./x.worker', import.meta.url), { type: 'module' })`; a new library is checked for sinks under the e2e suite before it lands.
- No CDN, inline script or third-party resource: fonts, images and scripts come from `public/` or the build; QR codes are drawn by `shared/ui/qr-code` with the app's own encoder (no library).
- Web as an app (plan v3 2.4): `@angular/service-worker` only in `core/updates/angular-service-worker.ts`. The worker caches only answers that are the same for everyone: a new cached path joins `ServiceWorkerCachedAnswersTest`'s probes and the anchored list of `core/updates/service-worker-bypass.ts`. A new version takes over only at a safe moment, never while `DirtyForms.any()`: every form registers through `appFocusFirstInvalid` or carries `appTrackedForm`. A reload the app starts by itself goes through `ReloadGuard.claim`. Build with `npm run build` (never `ng build` alone) for anything that ships or runs `e2e/pwa/`, because its `postbuild` prepends the payment route; any other code in the worker is a security change.
- Receipt PDF: pdfkit only in `receipt-layout.ts`, which only the worker and tests load; the layout takes its look from `ReceiptStyle` and the theme, and every word from the frozen receipt or the captions passed in.
- Receipt verification (`/overit`): WebCrypto `Ed25519`, `@noble/curves` only through `import()` where the browser lacks it; the trusted key list is replaced whole, never merged; jsQR only in `qr-decoding.ts`, loaded only by its worker; the camera starts only on the visitor's press and stops on a read, on stop, after two minutes and when the tab is hidden or left; only the exact prefix `https://nfnn.cz/overit#` with digits is accepted, and nothing read is ever opened or navigated to.
- Device copies (`core/device/`, plan v3 2.13 and 2.14, `docs/security-overview.md` "Device copies"): only WebCrypto and the Argon2id worker; every key non-extractable, the root key only in an open `OpenCopy` and zeroed by `close()`; every record and wrap sealed with AES-GCM and the additional data of `framed` (a new kind names its own label and fields there); hash-wasm only in `argon2.ts` and idb only in `idb-device-storage.ts`; a password key only through `WorkerPasswordKeyDerivation`, its parameters stored beside the wrap; no e-mail, name or user handle in the clear outside an open copy; the crypto core stores nothing itself (`scripts/device-crypto-storage.test.mjs`); the PRF input is per device and its output never leaves it, so `PasskeyAuthenticator` sends no `clientExtensionResults`; `DeviceVault` is the only writer, reached by the session only through `SESSION_DEVICE`, every change one transaction, and a new kind of stored value goes through it with a raw-storage canary test.
- Browser storage names (IndexedDB databases, storage keys, Web Lock and `BroadcastChannel` names) start with `nfnn.` (the older `nfnn-refresh` and `nfnn-session` stay) and are never renamed.
- Sessions: the access token only in memory (shared with other tabs over `nfnn-session`, never stored); the refresh cookie is the browser's; the `localStorage` flag only says a session may exist ("Cizí počítač" keeps it in `sessionStorage` and signs out after an hour without input); the installed app has its own lock, channel, flag and cookie; nothing else adds auth headers.

## i18n
- Every visible string has `i18n="@@<area>.<page>.<key>"`, the first segment one of `home`, `content`, `donor`, `admin`, `operations`, `layout`, `ui`; attributes `i18n-alt`, `i18n-aria-label`, `i18n-placeholder`; TS text with `$localize\`:@@id:text\``. Ids are stable, never renamed.
- The source locale is `cs`. Format through the cs-CZ helpers, one place per format, not Angular's locale pipes (`formatMinorUnits`/`formatCrowns`, `formatDonationDate`/`formatBankTime`/`formatPragueClock`, `formatMonth`/`formatMonthRange`, `formatReportMonth`); ICU plurals use `one`, `few` and `other` (`=0` only for a sentence of its own); TypeScript picks a form with `pluralCategory(count)`.
- Czech copy: no vocative or declension of names; sentence case; the donate action is "Přispět"; amounts from the API through `formatMinorUnits` (crowns typed by a visitor through `formatCrowns`) followed by `&nbsp;Kč` in a template and `\u00a0Kč` in TS; dates `15. 3. 2026` and times `15. 3. 2026 8:05`, no leading zeros except the minutes (ČSN 01 6910, Jakub 2026-11-06), the receipt PDF too; bank times in Prague time; backend titles and details shown as they come.

## UI (the look)
- The look is a swappable theme, independent of behaviour (Jakub 2026-10-23): the theme owns every value of the look, a component only its structure, and replacing the theme restyles the whole site without touching a template, a component's SCSS or any TypeScript. The control theme proves it (`E2E_THEME=control npx playwright test e2e/theme.spec.ts`); a new page gets a line in `e2e/theme.spec.ts`.
- Tokens live only in the theme on `:root`; a new token goes into every theme in the same PR (`npm run lint:styles` runs `scripts/check-themes.mjs`, which also checks receipt colours and fonts, tab bar contrast, the dark block and the themes' assets). A missing value is a new token in the theme (pick the nearest existing one first; a value used once is no reason for a token), never an inline value or a lint exception: Stylelint refuses raw colours, fonts, sizes, weights, line heights, letter spacing, radii, shadows, `px` spacing other than a 1 px hairline, durations and `width` media queries in components.
- Breakpoints only through `@use 'breakpoints' as bp;`, heights through `bp.height-down`; a new width or height is a new name there and in `core/layout/breakpoints.ts` (`scripts/breakpoints-parity.test.mjs`). Code that must choose a layout asks `CompactLayout.isCompact()` (a list that is a table on wide screens: `CompactLayout.listsAsRows()`) or `ShortViewport.isShort()` and renders one layout with `@if`, never two hidden by CSS. A layout that must give way to enlarged text asks a size container (`bp.container-down`); a container goes on a component's own box, never on a shell that holds a fixed bar.
- Shared building blocks are the global `ui-` classes of `src/styles/ui/`: a page, card, notice, button, list or table uses them and never copies their declarations; its SCSS keeps only layout and the rare override; an element keeps its own semantic class beside them where specs or layout need a hook; a look used in two features becomes a new block there. Behaviour with a template stays a component in `shared/ui/`.
- Translucency with `color-mix()`, never `rgba()`; fonts self-hosted; nothing loads from another origin. Tables become cards at `bp.down(cards)` (`data-label` per cell); fluid sizes are `clamp()` tokens; `prefers-reduced-motion` stops animations.
- Touch like a native app (#380, #385): controls are neither selectable nor draggable and have no tap flash or callout, while content text, bank details, fields and links in running text keep selection; every enabled control shows a pressed state through `@use 'pressed'`; hover looks only inside `@media (hover: hover)` (`nfnn/hover-only-with-hover`).
- Short screens: a full-screen block is at least `var(--full-screen-height)` (`100svh`; `100svh` plus the top inset in the iOS home-screen app, never `100lvh`, which overflows an app added with a solid status bar, `docs/frontend-overview.md`) and grows with its content, keeps the safe-area insets beside its text, the header's room above and `--tab-bar-clearance` under it; a page that wants the strip under Safari's toolbar dark colours `body`; text never runs over the face in a photo (`e2e/first-screen.spec.ts`).
- The top safe area: what sits below it takes `var(--safe-area-top)`, never `env(safe-area-inset-top)`, so the iOS home-screen app can add `--home-screen-top-clearance` below its status bar, out of Safari's blur (`docs/frontend-overview.md`).
- iPad windows (#396): a new fixed or sticky control at the top-leading corner keeps `--window-controls-inset-inline` or `-block` beside it (`e2e/window-controls.spec.ts`).
- Images: everything that can be SVG is SVG (Jakub 2026-10-30); raster only where no SVG can do (photos, and where a platform takes only raster). Photos are WebP with sized variants, `srcset`/`sizes`, `width`/`height`, `loading="lazy"` before `src` below the fold, `fetchpriority="high"` for the hero, decorative ones `alt=""`; the logo is a theme asset and its star keeps its face; icons inline SVG `aria-hidden="true" stroke="currentColor"`, the tab bar's filled with `fill="currentColor"`; no emoji in UI text.
- Budgets in `angular.json`: initial bundle warns at 500 kB, component styles at 4 kB.

## UX (how it behaves)
- Offline (plan v3 2.7): whether the app is offline comes only from `Connectivity`, which trusts the browser only when it says offline, never when it says online; nothing waits on a network `Connectivity` knows is gone. Every control that needs the server carries `appNeedsConnection` (`scripts/needs-connection.mjs`, run by `npm run lint`; a control that works offline goes into its `WORKS_WITHOUT_CONNECTION` with the reason), also where the check cannot see the call. A new fixed or sticky bottom bar rises above the offline pill. Public data shown from a copy says how old it is and that it "nemusí být aktuální".
- Every action shows loading, success (`role="status"`) and failure (`role="alert"` with the backend title/detail or a Czech sentence saying what to do next); a running request disables its button and names what happens. A `role="status"` element is always rendered with the `@if` inside it (a page's line through `<app-live-notice>`), except a line that appears with a page or a whole new view (the first loading line, a wizard step that takes focus); `role="alert"` may be inserted with its text; an app-shell notice is an always rendered `aria-live="polite"` region without `role="status"`, so each page keeps exactly one status region.
- Forms: visible labels, hint before error, error at the field in its own words, focus to the first invalid field, placeholders never the only label, every password field inside `<app-password-reveal>`.
- Dialogs through `<app-dialog>` on native `<dialog>`; every dialog keeps a step in the site's own history through `DialogHistory` (only the sign-in dialog and a navigation guard's unsaved-changes dialog set `[pushesHistory]="false"`); a sheet goes down under the finger, a control inside it that needs its own vertical drag is one `canPullSheetFrom` leaves alone, and a sheet whose page sets `[unsavedInput]` (input that took effort and is kept nowhere else) asks "Zahodit rozepsané údaje?" first; the sign-in dialog stays full-screen on phones without the gesture (experts' decision for #382); something behind a modal that must be heard announces through `DialogAnnouncer`.
- Accessibility (Jakub 2026-10-23): WCAG 2.2 AA for keyboard, screen readers, zoom and system settings, without changing the default look or behaviour; a visible change made for it needs Jakub's OK (he declined darker field borders and stopping the hero scroll dot: those change only under `prefers-contrast: more` and `prefers-reduced-motion`).
  - Semantics: native elements first; one `main#obsah` per shell behind the skip link "Přeskočit na obsah" (top-left, Jakub 2026-10-18), named `nav` landmarks, one `h1`, headings in order; exclusive choices use `appRadioGroup`, toggles `aria-pressed`, disclosures `aria-expanded`/`aria-controls`; an `aria-label` contains the visible text.
  - Focus: the 3 px `--color-focus-ring` outline on `:focus-visible` for every control, never removed without a replacement of the same colour; after a route change the shell focuses the page `h1`, after an in-page link the target section (`tabindex="-1"`, no ring); `scroll-padding-top` keeps focus from under the fixed header; dialogs and panels return focus to the opener; an overlay closes when focus leaves it.
  - Size: type in `rem`; pages hold at 320 px, at 200 % text and with WCAG text spacing; targets at least 24 px, and on a touch screen a small control reaches 44 pt through `touch-target.reaches-finger-size` without growing visibly (`e2e/touch-targets.spec.ts`).
  - Zoom (Jakub 2026-10-31, plan v3 2.23d): the page never zooms (`maximum-scale=1`, `PagePinchLock`, `touch-action: manipulation`), never `user-scalable=no`; text size is the browser's or, in the home-screen app on iPhone and iPad, the system's (Dynamic Type through `SystemTextSize`, 17 px at the default size, Jakub 2026-11-05, Q13), so a layout must hold at 200 % text. A new photo or QR shown to visitors sits in `<app-zoomable>`. axe's `meta-viewport` rule is off for this decision alone; the trade-off Jakub accepted: people who pinch to read must use the text size instead.
  - Largest text (#389, #390, #392): what must stay one row of fixed height caps its text by the viewport and keeps its accessible name whole; heading tokens grow only as far as a long Czech word fits the line and never below body text; `h1`–`h3` take `overflow-wrap: break-word`, never `hyphens: auto`; what may wrap wraps (`e2e/largest-text.spec.ts`).
  - System settings: `prefers-reduced-motion` stops motion, `prefers-contrast: more` darkens text and borders, `forced-colors` keeps buttons, selected states and focus visible; no state by colour alone.
  - Appearance (#347, Jakub 2026-11-06): the device's Light / Dark appearance is followed; every theme ends with a `prefers-color-scheme: dark` block of colour tokens; a colour that is both text and fill is two tokens and a new filled control takes the `-fill` token; what must not follow the device keeps a token the same in both (QR, logo, `--receipt-*`, `--color-paper*`), and the manifest colours stay light; a picture made for a light page gets a `<picture>` source with `media="(prefers-color-scheme: dark)"` (the logo) or `--filter-ink` and `--blend-ink` (uploaded ink) (`check-themes.mjs`, `e2e/dark-appearance.spec.ts`).
  - Tests: axe on every page and dialog (`e2e/accessibility.spec.ts`); keyboard, zoom, text size and spacing in `e2e/accessibility-keyboard.spec.ts`.
- Session loss never leaves a dead page: the donor goes home with the sign-in dialog; an expired token refreshes silently once.
- Money and bank details get copy buttons; on phones the bank details precede the QR code; delays are explained ("Údaje z banky k …", hourly import).
- The site never claims what the system does not do; placeholder content is named as such in the PR until Jakub supplies real content.
- Before handing a visual change over: screenshots at 390 and 1280 px of the states you changed (skill `visual-check`), audited by you for cut-offs, overlaps and contrast; before/after attached to the PR.
