# Frontend rules: Angular, UI, UX

## Angular 22 (standalone, zoneless, signals)
- Components: flat names `hero.ts/.html/.scss`, class `Hero` (no `Component` suffix), selector `app-*`, no `standalone: true` (default), no NgModules. Change detection is OnPush (Angular 22's default; the existing components still spell it out, a new one may omit it); never `ChangeDetectionStrategy.Eager`/`Default` (lint rejects it). So a template may read only signals, inputs and what its own events change: state that arrives otherwise (the forms API, a subscription) goes through a signal, as `appFormControl` turns the control's events into `showsError()` and `errorKey()`.
- State in `signal`/`computed`/`linkedSignal`; `input()`, `output()`, `model()` instead of decorators; `inject()` instead of constructor parameters; a parameterless constructor holds the start-up work (initial load, `effect`, `afterNextRender`, `DestroyRef.onDestroy`); `host: {}` metadata instead of `@HostListener`/`@HostBinding` (lint: `prefer-host-metadata-property`); no `any`; strict TS and templates stay on.
- Templates: `@if/@for/@switch/@defer`; `[class.x]`/`[style.x]` (no `ngClass`/`ngStyle`); import only the directives and pipes used (never `CommonModule`); logic in the class.
- Forms: template-driven `ngModel` inside `<app-form-field label hint [messages]>` with `appFormControl` (needs `id` + `ngModel`) and `form[appFocusFirstInvalid]`; the field shows its own first error after touch or submit (`aria-invalid`, `aria-describedby`); a form-level alert only for what no field owns (passwords differ, an API refusal). Signal Forms are stable in Angular 22 but not used here: switching means migrating `form-field`, `appFormControl` and every form at once, so only by decision.
- Local first (`backend.md`): compute and render here whatever the data already in the browser allows; the backend only serves it.
- HTTP and data: one `providedIn: 'root'` service per backend resource, `<name>-api.ts` in its feature folder (sign-in and account calls: `core/auth/auth-api.ts`), relative `/api/...` only, DTO interfaces mirroring `docs/api-contract.md`; a component calls it and `subscribe`s into signals, as every existing page does (no `httpResource`/`rxResource` piecemeal). Every call passes `authInterceptor` (Bearer header, problem+json Blob parsing, one refresh on `auth/expired-token`); errors become one line through `describeProblem` (`core/auth/api-problem.ts`). The HTTP backend is fetch, Angular 22's default (`withFetch()` in `app.config.ts` is deprecated and can go). Fetch reports no upload progress, and `reportUploadProgress: true` under it throws NG02824: an upload progress bar needs `withXhr()` in place of `withFetch()` for the whole app, plus `reportUploadProgress` (`reportProgress` is deprecated since 22.0).
- Routing: lazy per feature (`<feature>.routes.ts`, `loadChildren`/`loadComponent`), `title` via `$localize`, addresses and section ids in Czech without diacritics (`/darce/prehled`, `/sprava`, `/#prispet`; only `/api/...` stays English), `/darce/**` behind `donorGuard`, `/sprava/**` behind `adminGuard`, public shell with header and footer, unknown paths show `not-found` (nginx answers 200 for every path).
- Formatting is Prettier's (`.prettierrc`: 100 columns, single quotes, Angular parser for templates): run `npm run format` before committing; CI fails on a file it would change.
- Lint is ESLint with angular-eslint (`eslint.config.js`: recommended TypeScript and template rules, template accessibility, `prefer-inject`, `prefer-signals`, `prefer-output-readonly`, `prefer-on-push-component-change-detection`, `prefer-control-flow`, `prefer-self-closing-tags`): run `npm run lint` before committing; CI fails on a finding. Two scoped exceptions, both for the native `<dialog>`: `autofocus` is allowed in `*dialog*.html` because the dialog moves focus to it on open, and `shared/ui/dialog/dialog.html` closes on a backdrop click without key events because Esc closes it natively.
- Folders: `features/{content,donors,donations,contact,operations}` mirror backend contexts; `features/admin` holds every `/sprava` page whatever context it calls (a new page: `features/admin/<page>/`, calls in `admin-api.ts` unless the context already has a feature service for both sides, as content's `news-api.ts` and `projects-api.ts`, a route in `admin.routes.ts`, an entry in `ADMIN_SECTIONS`); singletons in `core/`; a behaviour-only piece used twice moves to `shared/ui/` (`form-field`, `dialog`, `copy-button`, `password-reveal`, `qr-code`, `markdown` for content bodies, `side-nav` for the side panel of `/sprava` and `/darce`).
- No CDN, inline script or third-party resource (CSP rule in `security.md`): fonts, images and scripts come from `public/` or the build, and QR codes are inline SVG drawn by `shared/ui/qr-code` from the module matrix (the saved PNG goes through a `data:` image and a canvas).
- Sessions: access token in memory (`AuthStore`), refresh cookie set by the browser, `localStorage` flag `nfnn.donor-session` only says a session may exist; nothing else adds auth headers.

## i18n
- Czech source: every visible string has `i18n="@@<area>.<page>.<key>"`, the first segment one of `home`, `content`, `donor`, `admin`, `operations`, `layout`, `ui` (follow the neighbouring component); attributes `i18n-alt`, `i18n-aria-label`, `i18n-placeholder`; TS text with `$localize\`:@@id:text\``. Ids are stable, never renamed. There is no translation file yet.
- The source locale is `cs` (`angular.json` `i18n.sourceLocale`, so the build carries the Czech locale data and `LOCALE_ID` is `cs`; specs get the same from `src/test-providers.ts`). Format through the cs-CZ helpers, one place per format, not Angular's locale pipes: `formatMinorUnits`/`formatCrowns` (`donation-amount.ts`), `formatDonationDate`/`formatBankTime` (`donation-date.ts`), `formatMonth`/`formatMonthRange` (`donation-month.ts`), `formatReportMonth` (`admin/report/report-month.ts`); ICU plurals use the Czech categories `one`, `few` and `other` (`=0` only for a sentence of its own); TypeScript picks a form with `pluralCategory(count)` (`core/i18n/plural-category.ts`, over `Intl.PluralRules('cs')`).
- Czech copy: no vocative or declension of names (show the name alone); sentence case; the donate action is "Přispět"; amounts from the API (hellers) go through `formatMinorUnits(minor)` (crowns typed by a visitor through `formatCrowns`), which gives `1 000` or `1 000,50`, followed by `&nbsp;Kč` in a template and `\u00a0Kč` in TS; dates `15. 03. 2026`; bank times in Prague time; backend titles and details are shown as they come (already localized).

## UI (the look)
- The look is a swappable theme, independent of behaviour (Jakub 2026-10-23, plan `/mnt/project-files/nfnn-ux/oddeleni-vzhledu.md`). The theme owns every value of the look; a component owns only its structure (which grid, flex or order, which widths of its own content, which token for which part). Replacing the theme must restyle the whole site without touching a template, a component's SCSS or any TypeScript.
- A theme is a folder `src/themes/<name>/` with `_theme.scss` (its `@font-face` rules and every token on `:root`, plus at most rules that restyle the `ui-` blocks) and its fonts; `styles.scss` loads it as `@use 'theme'` from the include path, so the build picks the theme: `nova-nadeje` by default, `control` with the configuration `control-theme` (`ng build --configuration=production,control-theme`, `ng serve --configuration=control-theme`). The control theme is deliberately different (teal, system fonts, square corners, 5 px spacing unit) and exists only to prove the swap: CI builds it and `E2E_THEME=control npx playwright test e2e/theme.spec.ts` opens every public page, the sign-in dialog, every `/darce` section and every `/sprava` page and fails on any colour or font of `nova-nadeje` that the control theme does not share. A new token goes into every theme in the same PR: `npm run lint:styles` runs `scripts/check-themes.mjs`, which fails when a theme misses a token the styles use or `nova-nadeje` sets. A new page gets a line in `e2e/theme.spec.ts`.
- Tokens live only in the theme (`src/themes/nova-nadeje/_theme.scss`) on `:root`: colour by role (`--color-accent*`, `-text*`, `-surface*`, `-border*`, `-focus-ring`, `-danger*`, `-warning*`, `-success*`, `-on-*`), fonts (`--font-serif` Playfair, `--font-sans` Inter, `--font-mono`, `--numeric-figures`), type size in `rem` (`--text-2xs` 11 px … `--text-6xl` 44 px at the default 16 px, and fluid roles `--text-heading`, `-section-title`, `-section-title-compact`, `-cta-title`, `-article-title`, `-page-title`, `-hero`), weight (`--weight-regular` … `-extrabold`), line height (`--leading-none`, `-display`, `-heading`, `-snug`, `-normal`, `-relaxed`, `-loose`), letter spacing (`--tracking-tight`, `-slight`, `-wide`, `-widest`), spacing (`--space-<n>` = n × `--space-unit` 4 px, half steps `-0-5`, `-1-5` …, so a theme changes density with one value), shape (`--radius-*`), depth (`--shadow-*`, one per role), motion (`--duration-fast`, `-base`, `-slow`, `-entrance`), layout (`--content-max`, `--header-height`, `--floating-notice-height`, `--side-nav-layout-max`, `--side-nav-width`, `--top-bar-height`).
- Breakpoints only through `@use 'breakpoints' as bp;` (`src/styles/_breakpoints.scss`, on the include path): `@include bp.down(phone)` is `max-width`, `bp.up(cards)` is `min-width` one pixel above; names `tiny` 360, `narrow` 420, `phone` 480 (dialogs full-screen), `cards` 640 (tables as cards), `tablet` 768, `nav` 899 (side panel collapses). A new width is a new name there, never a raw `@media`.
- `npm run lint:styles` (in CI) rejects in components a raw colour, font, font size, weight, line height, letter spacing, radius, shadow, a `px` spacing other than a 1 px hairline (`padding`, `margin`, `gap`), a transition duration and a `width` media query. A missing value is a new token in the theme (pick the nearest existing one first; a value used once is not a reason for a token), never an inline value or a lint exception.
- Shared building blocks are global classes in `src/styles/ui/` (prefix `ui-`, BEM modifiers, loaded by `styles.scss` after the form controls): `_page` (`.ui-page`, `-head`, `-title`, `-intro`, `.ui-crumbs`), `_card` (`.ui-card`, `--danger`, `--padded` for a card whose content sits on its padding, `__title` with `--large`, `__subtitle`, `__bar` for a heading strip over a table or list, `__body`, `__intro`, `__empty`, `__footer`; `.ui-data-list` for a `dl` of label and value), `_notice` (`.ui-notice--status|--alert`, `--floating` for a bar fixed at the bottom of the screen with `__text` beside its button (the page keeps room for it through `:root.has-floating-notice` and the layout token `--floating-notice-height`, `0rem` in the theme and measured by the component that shows it), `.ui-load-state` `--error`, `--inset`, `.ui-badge--success|--warning|--accent`, `.ui-mono`, `.ui-callout--danger|--warning` for a framed message inside a card), `_button` (`.ui-button` soft accent, `--primary`, `--small`, `--quiet`, `--large` beside a primary, `--danger`, `--danger-soft`, `--danger-outline`, `--block` for a full-width form submit; `.ui-link-button`), `_table` (`.ui-table`, cards at `bp.down(cards)`), `_form` (`.ui-field-error` under a form, `.ui-segmented` choice of two or three buttons with `.is-active`, `.ui-form-status` for the saved line after a form), `_action-bar` (`.ui-action-bar`: the sticky bar at the bottom of the viewport that ends a long form, with `appActionBar` from `shared/ui/action-bar` so `scroll-padding-bottom` keeps the focused field above it), `_panel` (a standalone page such as the password reset: `.ui-panel-page` around `.ui-panel`, `__title`, `__lead`; `.ui-status` with `__icon`, `--warning`, `--spinner` for a result or a wait), `_section` (the public site: `.ui-container` for the content width of a section, `.ui-eyebrow` above a section title with `--on-inverse` and `--accent-on-inverse` on a dark background, `.ui-intro` for the dark band that opens a page with `__title` (`--article` for a news or project title) and `__lead`, `.ui-cta` for a large call to action with `--ghost` and, on top of it, `--on-inverse` or `--on-image`). A page, card, notice, button or table uses them in its template and never copies their declarations; its SCSS keeps only layout and the rare override (a margin, a narrower width). An element keeps its own semantic class beside the `ui-` ones where specs or layout need a hook (`class="ui-button ui-button--primary profile-save"`). A look used in two features becomes a new block there, not a copy. Behaviour with a template stays an Angular component in `shared/ui/`.
- Translucency with `color-mix()`, never `rgba()`. Fonts self-hosted variable WOFF2; nothing loads from another origin.
- Tables become cards at `bp.down(cards)` (`data-label` per cell); fluid sizes are `clamp()` tokens; `prefers-reduced-motion` stops animations (global rule in `styles.scss`).
- Images: WebP in `public/images/` (except `og-image.jpg` for link previews and `logo.svg`), sized variants with `srcset`/`sizes`, `width`/`height`, `loading="lazy"` written before `src` below the fold, `fetchpriority="high"` for the hero, decorative photos `alt=""`; icons inline SVG `aria-hidden="true" stroke="currentColor"`; no emoji in UI text.
- Budgets in `angular.json`: initial bundle warns at 500 kB, component styles at 4 kB.

## UX (how it behaves)
- Every action shows loading, success (`role="status"` line) and failure (`role="alert"` line with the backend title/detail or a Czech sentence saying what to do next); a running request disables its button and names what happens ("Připravujeme PDF…"). Put `role="status"` on an element that is always rendered and the `@if` inside it (`<p role="status">@if (msg()) {<span>{{ msg() }}</span>}</p>`, as in `passkeys-card.html`): a status element inserted together with its text is often not announced. `role="alert"` may be inserted with its text. A page's success-or-failure line is a `Notice` (`{ kind: 'status' | 'alert', text }`) shown by `<app-live-notice [notice]="…" />` (`shared/ui/live-notice`), which keeps both regions rendered; elsewhere wrap the `@if` in `<div role="status">`. A line that appears with a page or with a whole new view (the first loading line, a wizard step that takes focus) may stay inside its `@if`. Specs read these regions as `[role="status"]:not(:empty)`, e2e as `getByRole('alert').filter({ hasText: /\S/ })`.
- Forms: visible labels, hint before error, error at the field in its own words, focus to the first invalid field, placeholders never the only label, every password field inside `<app-password-reveal>`.
- Dialogs through `<app-dialog>` on native `<dialog>` (`showModal()`: focus trapped, Esc, backdrop and × dismiss, focus returns to the opener); shared open state in a service (`LoginDialogService.open(mode, options)`).
- Accessibility (Jakub 2026-10-23): WCAG 2.2 AA for keyboard, screen readers, zoom and system settings, without changing the default look or behaviour; a visible change made for it needs Jakub's OK (he declined darker field borders and stopping the hero scroll dot: those change only under `prefers-contrast: more` and `prefers-reduced-motion`).
  - Semantics: native elements first; one `main#obsah` per shell behind the skip link "Přeskočit na obsah" (top-left, Jakub 2026-10-18), named `nav` landmarks, one `h1`, headings in order; exclusive choices use `appRadioGroup` (`shared/ui/radio-group`: arrows, Home/End, roving `tabindex`), toggles `aria-pressed`, disclosures `aria-expanded`/`aria-controls`; an `aria-label` contains the visible text; live regions `role="status"`/`role="alert"`.
  - Focus: the 3 px `--color-focus-ring` outline on `:focus-visible` for every control, never removed without a replacement of the same colour; after a route change the shell focuses the page `h1`, after an in-page link the target section (`tabindex="-1"`, no ring); dialogs and panels return focus to the opener; an overlay closes when focus leaves it; `scroll-padding-top` keeps focus from under the fixed header.
  - Size: type tokens in `rem`, so the browser's text size applies; pages hold at 320 px and with WCAG text spacing (nothing cut off, single grid columns `minmax(0, 1fr)`); targets at least 24 px.
  - System settings: `prefers-reduced-motion` stops motion, `prefers-contrast: more` darkens text and borders (theme), `forced-colors` keeps buttons, selected states (`aria-pressed`/`-checked`/`-current`) and focus visible (`styles.scss`); no state by colour alone.
  - Tests: axe on every page and dialog (`e2e/accessibility.spec.ts`); keyboard, zoom, text size and spacing in `e2e/accessibility-keyboard.spec.ts`.
- Session loss never leaves a dead page: the donor goes home with the sign-in dialog; an expired token refreshes silently once.
- Money and bank details get copy buttons; on phones the bank details precede the QR code; delays are explained ("Údaje z banky k …", hourly import).
- The site never claims what the system does not do; placeholder content is named as such in the PR until Jakub supplies real content.
- Before handing a visual change over: screenshots at 390 and 1280 px of the states you changed (skill `visual-check`), audited by you for cut-offs, overlaps and contrast; before/after attached to the PR.
