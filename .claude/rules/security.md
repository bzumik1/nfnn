# Security rules

Threat model: a public site (public repository) whose donor accounts yield tax receipts in the donor's name, with an administration reachable from the browser and from connected AI clients. Prevent: reading another donor's data, a receipt in another name, administrator takeover, abuse of e-mail sending, exhausting the server. How each mechanism works is in `docs/security-overview.md` (update it in the same PR); endpoints and problem codes in `docs/api-contract.md`. These rules hold whatever the task; weakening one needs Jakub's OK in the PR.

- Access: everything under `/api` needs the donor JWT unless listed `permitAll` in `ApiSecurityConfiguration`; resources are found by the JWT subject; another donor's resource answers 404, never 403. A new endpoint gets a 401 scenario and, for a donor resource, a 404 one for another donor; a new public endpoint also gets its `permitAll` line and a rate limiter.
- Administration: `/api/admin/**` needs `ADMIN`, which enters the JWT only for a session opened with the second factor (TOTP or passkey). The role is granted and removed only by another administrator in the web GUI (the first one from `ADMIN_EMAILS` while the site has none), never by oneself, never by SQL. Every administrator's change publishes `AdminActionPerformed`. An administrator who holds a second factor changes a second factor or passkey only from a session opened with it, and reset-link recovery is refused to an administrator, so a stolen mailbox cannot enrol an attacker's factor.
- Connected applications (a token with a `scope` claim): a change needs `admin:write`. The dangerous or irreversible actions stay web-only (Jakub 2026-10-23): deletions, older-symbol reversals, the administrator role, second-factor and passkey resets, GDPR erasure, secrets, the site address (`PUBLIC_URL`) and the applications allowed to connect (`OAUTH_CLIENT_HOSTS`), the receipt signature (the connector only reads whether one is set), backup download and restore, approving a connection, the administrator's own account. Web-only means guarded by `BrowserSessionAuthorizationManager` in `ApiSecurityConfiguration` (or, where one endpoint serves both kinds of token, a check of the `scope` claim in the controller, as `AdminSettingsController` does for secrets) with a 403 scenario in `connected_apps.feature`. Every item on the list is guarded so (`BROWSER_ONLY_DELETES`, `BROWSER_ONLY_POSTS`, security audit 2026-10-23), and a new endpoint for any item on the list gets the guard and its row in the scenario outline. A missing MCP tool is not a control, because whoever holds a connector token can exchange it for an API token.
- MCP connector: holds no secret and validates no token itself (it exchanges every bearer token at the backend); its tools reach only `/api/admin/**` and `/actuator/{health,info}`, and it calls the token endpoint only to exchange tokens; it has a tool for every setting and all data of the administration except the web-only list. A new tool that reveals names or addresses beyond what the API already returns to an administrator is a security change.
- Credentials and one-time secrets: passwords only through `BCryptPasswordHasher`; an unknown e-mail or a password-less account still costs the `UNKNOWN_DONOR_HASH` compare; no endpoint reveals whether an address is registered. Reset and verification links, challenges and codes are random, stored only as SHA-256, short-lived, single-use and marked used before any check; link secrets travel in the URL fragment. The password and the e-mail change only with the current password (or the donor's own passkey) and revoke every other session; a new address is confirmed from that address and the old one is told. Turning the second factor on or off needs the password and a code and revokes every other session. Adding a passkey needs the current password or a passkey and e-mails the donor. A new credential change does at least as much as the closest of these. Refresh tokens rotate; a replay ends every session.
- First setup (`/api/operations/setup…`): public only until completed (then 409); without the code only for `X-Nfnn-Direct` from the frontend nginx plus a private client address (`HomeNetworkRequests`); the setup code goes to standard output only, never to `backend.log` or the log API.
- Abuse: every endpoint that checks a guessable secret (password, TOTP code, setup code), sends mail or triggers an outbound request has a per-address limiter built like `SignInRateLimiter`, checked before any hashing or work (the table is in `docs/security-overview.md`); endpoints keyed only by a 256-bit secret need none. The client address is the one the frontend nginx resolved; the backend trusts forwarded headers from any peer, so port 8080 is never published, the containers sit on their own networks (`nfnn-edge`, and `nfnn-internal` without a way out for postgres and the backup) instead of the default bridge other apps on the server share, nothing else relays client headers to it, and a server-to-server call that hits a limiter must carry the visitor's address.
- Outbound requests (client metadata documents in the backend, photos in the connector): `https` only, every resolved address checked against private, loopback, link-local and reserved ranges, redirects none or re-checked, a timeout and a size cap.
- Input: Bean Validation with explicit `@Size` on every request record, value objects validate again, honeypot on public forms; JPA parameters only (no string-built queries).
- Output: `server.error.include-*: never`; problem+json carries no stack trace or exception text; Thymeleaf `th:text` only; Angular bindings only (no `innerHTML`).
- Secrets: never in compose, code, docs, tests, URLs, logs, PRs or commit messages; on the server generated into `secrets/` or sealed in `operations_setting`, never returned by an API, changed only from a browser session; the stored SMTP password goes only to the server it was saved for (moving host, port, user or STARTTLS needs the password in the same change, the mail test uses it only against the running server); locally only `.env`. `JWT_SECRET` and `SETTINGS_KEY` have defaults only in `application-dev.yml`. A value object, `@ConfigurationProperties` record or request/response record that holds a password, secret or token masks `toString` (`RawPassword`, `FioImportProperties`).
- Logs (backend, connector, nginx): ids and outcomes only, never names, e-mails, addresses, query strings, tokens or message bodies. A new log field, a new `log_format` or a log of a full exception whose message may carry data (SQL, SMTP) is a security change. Framework loggers above INFO write request and response bodies, headers or SQL values into logs that connections read: `ProtectedLoggers` pins those that do at DEBUG at INFO and refuses to change them, TRACE is refused for every logger outside `cz.novanadeje.app` (ROOT included), and a logger found to leak data at DEBUG joins `ProtectedLoggers` with its pin in `application.yml`. Raise a level (`nfnn_set_log_level`, `/sprava/logy`) preferably for `cz.novanadeje.app…`.
- Browser: the Content-Security-Policy in `frontend/nginx-security-headers.conf` allows no inline script and no third-party resource; an inline script, an external resource or a new kind of embed extends it in the same PR, verified against the production nginx (skill `visual-check`); `inlineCritical` stays off in `angular.json`; CORS stays unconfigured (same origin).
- Data protection: collect only what receipts and pairing need; contact messages are deleted after a year; the privacy policy changes with the feature that changes the data.
- Supply chain: supported majors only; every package manifest (`backend`, `frontend`, `mcp`) is covered by Dependabot; a new dependency needs a reason in the PR and, for a library, an ArchUnit rule confining it to adapters; workflows use `persist-credentials: false` and minimal `permissions`; official base images; application processes run unprivileged (the entrypoints hand Java to `app` with `setpriv` and Node to `node` with `su-exec` after the root-only setup), and a new one does the same.
- Unsure whether something is sensitive? Treat it as sensitive and ask Jakub in the PR.
