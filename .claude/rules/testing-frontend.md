# Testing rules: frontend

The general rules (TDD, given/when/then naming) are in `testing.md`. How the e2e server, the fixtures, the device steps, the Safari runner and the web-app fixture work: `docs/frontend-overview.md` "Frontend conventions in detail", Testing.

## Frontend
- Vitest specs beside the code (`name.spec.ts`): `describe('Given …')` → `it('when …, then …')`, or a nested `describe('when …')` with `it('then …')` when outcomes share a setup. TestBed with `provideHttpClient()`, `provideHttpClientTesting()` (`http.verify()` in `afterEach`) and `provideRouter([])`; drive the DOM and assert visible text and ARIA, not internals; fixtures in `*/testing/`. `src/test-providers.ts` gives every TestBed the `cs` locale and `FakeLiveUpdates`, so no spec opens the live stream unless it provides the real service.
- Playwright in `e2e/` by user journey, same naming. Nothing may reach a backend: `npm run e2e` serves the production build like the frontend nginx, under its security headers, and proxies nothing. Specs import `test` and `expect` from `e2e/fixtures.ts` (lint refuses `@playwright/test`), whose automatic fixture answers unmocked `/api` calls with a 404 problem, fails a journey that asks the server for a payment QR, and fails any test during which a page reported a CSP violation (a test that plants one on purpose asserts it and empties the list). Each spec mocks the calls its journey needs (`mockDonorApi`).
- An administrator's remembered session finds the administration locked: the automatic fixture unlocks it before a locator action or assertion, so a spec that first waits on a response or runs axe acts on the page (or calls `unlockAdministration(page)`) first, and a spec about the lock sets `test.use({ unlocksAdministration: false })`.
- CI fails a test that passed only on a retry (`failOnFlakyTests`). A test that fails only sometimes is a race in the app or the test: reproduce it and fix it test-first, never retry it away. Every test stands alone (3 workers, `fullyParallel`): no shared state, no order, each mocks what it needs. A browser service the headless shell lacks (password manager, passkeys) is stubbed with `page.addInitScript`.
- `signIn` at 1280 px, resize after; downloads through `page.waitForEvent('download')`; a new page or dialog gets its case in `accessibility.spec.ts` (axe, WCAG 2.2 AA).
- The project `iphone` (WebKit) runs the receipt PDF, `/overit`, Přispět, authenticator and Trusted Types journeys at phone size; a test that cannot run in WebKit skips with `test.skip(({ browserName }) => browserName !== 'chromium', reason)`, its reason naming what the device checklist covers instead. What WebKit in Playwright cannot show (a real share sheet, Files, the camera, printing) is Jakub's device checklist.
- Phones and tablets (`e2e/devices/`, `npm run e2e:devices`): every step of `STEPS` runs in every pose of `POSES` with the same layout checks. A finding the site has today is listed in `known-findings.ts` with its pose, steps, check, text and reason, and a step that cannot open in `KNOWN_BREAKS`; the test fails on any other finding and on a listed one that is gone, so a fix removes its entry in the same PR, and a new finding is fixed or, only by Jakub's decision, listed. The same steps run in real Safari (`npm run e2e:safari`, `safari.yml`). The checks see no pixels: review the screens yourself before handing over a visible change (skill `visual-check`).
- Web as an app (`e2e/pwa/`, `npm run e2e:pwa`, CI's `pwa` job; not part of `npm run e2e`): specs import `pwaTest` and `expect` from `e2e/pwa/pwa-fixtures.ts` (lint refuses the others) and route only on the context (lint refuses `page.route`; helpers take the context). The fixture fails a test on any console error, uncaught error or CSP violation of a page or worker; `test.use({ allowedConsoleErrors: [/…/] })` allows a text with its reason beside it, and `browserProblems.expectOne(/…/)` names a problem the test causes on purpose. Its nginx containers run on the host's network, never a Docker bridge (`pwa-fixtures.spec.ts`). After a killed run, remove only this worktree's containers and folders, found by their mounts, from this worktree's root: `for c in $(docker ps -aq --filter label=nfnn-pwa); do src=$(docker inspect -f '{{range .Mounts}}{{.Source}} {{end}}' $c); case "$src" in *"$(pwd -P)/frontend/"*) for d in $(docker inspect -f '{{range .Mounts}}{{.Source}} {{end}}' $c); do case $d in */nfnn-pwa-*) rm -rf "$d";; esac; done; docker rm -f $c;; esac; done`; an `nfnn-pwa-*` temporary folder no container mounts and older than a day may also go.
- A drawn receipt PDF is tested by what it says and does, read back with `receipt-pdf/testing/pdf-reader.ts`; the certified text is the shared case `shared-cases/receipts/v1/printed.json`.
- Test behaviour, text and accessibility, never style values. E2e runs against the production bundle; no spec relies on dev mode.
