# Testing rules: frontend

The general rules (TDD, given/when/then naming) are in `testing.md`.

## Frontend
- Vitest specs beside the code (`name.spec.ts`): `describe('Given …')` → `it('when …, then …')`; nested `describe('when …')` with `it('then …')` (or `it('and …, then …')`) when outcomes share a setup. TestBed with `provideHttpClient()`, `provideHttpClientTesting()` (`http.verify()` in `afterEach`), `provideRouter([])`; drive the DOM (events, `fixture.whenStable()`) and assert visible text and ARIA, not internals; fixtures in `*/testing/` (excluded from the app build); `src/test-setup.ts` polyfills `<dialog>` for jsdom and `src/test-providers.ts` (the `providersFile` in `angular.json`) gives every TestBed `LOCALE_ID` `cs` and `FakeLiveUpdates` (`core/live/testing/live-fixtures.ts`) for `LiveUpdates`, so no spec opens the live stream unless it provides the real service, and a spec drives hints with `hint(feed)` and `resync()`.
- Playwright in `e2e/` by user journey, same naming (`test.describe('Given …')`, `test('when …, then …')`). Nothing may reach a backend: `npm run e2e` builds the production bundle and serves it on :4200 with `scripts/serve-dist.mjs`, which answers like the frontend nginx (`index.html` for app routes, `index.html` with 404 for any other path that is no file, read from the map `$app_page` of `nginx.conf` through `scripts/app-routes.mjs`, 404 for a missing file, nginx's Content-Types with `charset=utf-8` for text, the security headers of `nginx-security-headers.conf` read through `scripts/security-headers.mjs` on every answer, so every journey runs under the production Content-Security-Policy and Trusted Types) and proxies nothing, and specs import `test` and `expect` from `e2e/fixtures.ts` (lint refuses them from `@playwright/test`): its automatic fixture answers every `/api` request no spec mocked with a 404 problem and serves the setup status, an empty home and the foundation's payment details, and fails any journey that asks for a path under `/api/donations/payment-` other than the payment details (the browser draws every payment QR itself) and any test during which a page of its context reported a `securitypolicyviolation` (`cspViolations`: a test that plants a violation on purpose, as `security-headers.spec.ts` does, asserts it and empties the list; the listener sits in each document, so a violation inside a worker counts only when it breaks the journey), and each spec mocks the calls its journey needs (`mockDonorApi` in `e2e/donor-session.ts` for donor and admin pages). An administrator's remembered session finds the administration locked (slice 2.19), so the automatic fixture `administrationUnlock` answers `POST …/devices/current/unlock` and `…/administration-copy` with 204 and unlocks it through the panel with a Playwright locator handler on the heading "Správa je zamčená"; a handler runs only before a locator action or assertion, so a spec that first waits on a response or runs axe still sits behind the lock and must act on the page (or call `unlockAdministration(page)`) first, and a spec about the lock itself sets `test.use({ unlocksAdministration: false })`. CI fails a test that passed only on a retry (`failOnFlakyTests`); with `E2E_DIST` set it serves that folder without building (CI, after its build steps), with `E2E_BASE_URL` set it tests that server and starts none, and locally it reuses a server already on :4200 (`npm start` while editing). `signIn` at 1280 px (the header button is hidden on phones), resize after; downloads via `page.waitForEvent('download')`; `accessibility.spec.ts` runs axe with WCAG 2.2 AA tags, so a new page or dialog gets a case there.
- Phones and tablets (after t3code's mobile e2e): `e2e/devices/` runs every step of `STEPS` (`steps.ts`: the public pages and tabs, Přispět with an amount, the sign-in and registration dialogs, `/overit`, the donor's sections and account sheet, the administration's pages and its page of further sections (`/sprava/vice`), a paired payment's sheet, the history and three parts of a donor card, each opened from the e2e mocks on its own) in every pose of `POSES` (`poses.ts`: a Playwright project `device-<pose>` each, WebKit with the iPhone SE (3rd gen), iPhone 17 Pro upright and on its side, iPhone 17 Pro Max with text at 200 %, iPad Pro 11 upright and on its side with text at 200 %, and Chromium as a Pixel 7; text through `html { font-size }` as the browser's text size sets it). Each step, opened and settled (no request in flight for two frames, so a page whose data comes after its heading is checked whole, and every finite animation finished, so a sheet is checked where it stops), runs the same layout checks (`layout-checks.ts`, from the page's own boxes, not its pixels; inside an open modal dialog only its controls): no script error, no sideways scroll of the page, no control cut off by the screen edge (fixed ones also at the top and bottom), no two controls stacked on each other (a button inside a text field excepted), no control covered by another element at its centre (content scrolled under a fixed bar, at the top once the page has scrolled and at the bottom until the page reaches its end, and a panel an open disclosure lays over it excepted), the focused control not under a fixed bar, every target at least 24 px or spaced as WCAG 2.5.8 allows from the targets of its own layer (inline links in a sentence excepted), no text cut off by a box that hides its overflow and no control cut off by one (a control partly or wholly outside, sideways, a box with `overflow` `hidden` or `clip` between it and its containing block, a scroller and a visually hidden box of 1 px excepted, as a table too wide for its card cuts off its last column's button at 200 % text); a page longer than the screen (no dialog open) is then scrolled to its end and checked once more for a covered control, so nothing at the end of a page hides under the tab bar (`at the end of the page:` in the finding). `layout-checks.spec.ts` (in the `chromium` project) plants each defect and each exception on a page of its own and proves which check fires. A finding the site has today is listed in `known-findings.ts` with its pose, steps, check, the text it shows and why (`KNOWN_FINDINGS`), and a step that cannot open on a pose in `KNOWN_BREAKS` (run as `test.fail`): the test fails on any other finding and on a listed one that is gone, so a fix removes its entry in the same PR and a new finding is fixed or, only by Jakub's decision, listed. The reporter `device-report.ts` writes every screen (CSS pixels) with its checks into `frontend/test-results/device-report/` (`index.html`, `report.json`), which CI keeps as the artifact `zarizeni`; `npm run e2e:devices` runs only these projects. The same steps also run in real Safari (`e2e/devices/safari.spec.ts`, a project `device-safari-<pose>` per pose of `SAFARI_POSES`: the smallest iPhone, the newest iPhone Pro, the newest iPhone Pro Max with text at 200 %, an 11-inch iPad on the iOS simulators the Mac has, and Safari on macOS at 1280 × 800, also with text at 200 %), which Playwright cannot drive: each step opens through the `Ui` of `e2e/devices/ui.ts`, which `devices.spec.ts` gives from the Playwright page and `safari.spec.ts` from a WebDriver session of `safaridriver` (`webdriver.ts`, the simulator chosen by name from `xcrun simctl list` and booted once the other booted ones are shut down, its Safari started again before the first session and after every refused one (up to five attempts, 10 s apart: a cold simulator's Safari sometimes does not answer `safaridriver` in time); a press whose control gets no `click` within 2 s, as the iOS simulator's element click sometimes sends only `pointerdown` and `touchstart`, is tried again as a touch tap and then as a script click, each try kept as a `press` annotation and printed), and the mocks reach Safari through `route-host.ts`, a server that serves the build like `serve-dist.mjs` and answers the same `page.route` registrations (the defaults of `e2e/fixtures.ts` and the guard on server payments included), puts the text size, the session flag and an error collector into `index.html` and counts the requests in flight for the settle wait; both specs share `run-step.ts`, so a step, a check and `known-findings.ts` mean the same in both. The Safari projects exist only with `SAFARI` set, which leaves out every other project and the web server, takes no retries and stops after ten failures (a failed test restarts the worker and so the Safari session; a failed step keeps its screen and the pointer, touch, click and focus events the page saw); `npm run e2e:safari` builds and runs them on one worker on a Mac with Xcode (`sudo safaridriver --enable` once), the same command as the workflow `safari.yml` (`deploy-ci.md`), and writes the same report. The checks see no pixels, so a thread reviews the screens itself before handing over a visible change (skill `visual-check`, Phones and tablets).
- Web as an app (slice 2.2, testing review 3.7): the Playwright project `pwa` (`default: false`, so `npm run e2e`, the CI shards and their shard check leave it out; `npm run e2e:pwa` or `--project=pwa`; CI's job `pwa`) runs `e2e/pwa/` in Playwright's full Chromium (`channel: 'chromium'`, new headless; the headless shell has no camera) with `serviceWorkers: 'allow'`, while every other project has `serviceWorkers: 'block'`. Its specs import `pwaTest` and `expect` from `e2e/pwa/pwa-fixtures.ts` (lint refuses `test` and `expect` from `@playwright/test` and `../fixtures` there): a worker fixture copies the production build (`E2E_DIST`, else `dist/frontend/browser`) into variants `a` and `b`, writes into each the marker `pwa-marker.txt` and the planted scripts `pwa-plant-sw.js` (a service worker of scope `/pwa-plant/`) and `pwa-plant-worker.js` (a dedicated worker), which on a message log a console error, throw or reach another site, and then regenerates `ngsw.json` with Angular's `ngsw-config` (since 2.4 the app's own `ngsw-worker.js` is the worker under test, the same file in both, so an update arrives through `ngsw.json` and `VERSION_READY`, not as a waiting worker), so `b` differs only in its marker, `ngsw.json` and its later modification time (nginx's ETag is time and size), and serves `html → a` with the real `nginx.conf` and `nginx-security-headers.conf` in a container of the image `frontend/Dockerfile` names, on the host's network with `listen 80` of a copy of `nginx.conf` turned into a port of its own on `127.0.0.1` (the only change to it; `--add-host backend` and `mcp`, so nginx starts, and its logs on a `tmpfs`; one container per worker, labelled `nfnn-pwa` and removed at its end, a retry on another port when nginx finds the free one taken in between; never on a Docker bridge, because each container started, stopped or removed there adds or drops a link on the host, and Chromium then fails the requests other workers have in flight with `ERR_NETWORK_CHANGED`, which `pwa-fixtures.spec.ts` guards by comparing the host's links around a site's start, stop, restart and removal; after a killed run, worktrees share the label, so find this worktree's containers by their mounts (`<worktree>/frontend/nginx-security-headers.conf` and the temporary root `nfnn-pwa-*`) and, from the repository root, `for c in $(docker ps -aq --filter label=nfnn-pwa); do src=$(docker inspect -f '{{range .Mounts}}{{.Source}} {{end}}' $c); case "$src" in *"$(pwd -P)/frontend/"*) for d in $(docker inspect -f '{{range .Mounts}}{{.Source}} {{end}}' $c); do case $d in */nfnn-pwa-*) rm -rf "$d";; esac; done; docker rm -f $c;; esac; done` removes only them and their folders (in bash and zsh alike, the worktree path resolved), and an `nfnn-pwa-*` temporary folder that no container mounts and that is older than a day may also be removed; `npm run e2e:pwa` builds the app first as `npm run e2e` does, and with `E2E_DIST` set `--project=pwa` alone builds nothing and starts no server on :4200). `site` switches the served variant (`switchTo`, an atomic symlink swap), lists `filesOnlyIn(variant)`, removes a file of the served variant (`remove`, as when the server keeps only the latest chunks), stops and starts the container (`takeDown`, `bringUp`: unreachable, connection refused), turns the service worker off on the server (`turnServiceWorkerOff`, the flag `/logs/service-worker.off` of `deploy/README.md`), and is reset to `a` with every file back after each test, so tests in a worker never see each other's switch. Every API path is routed on the context (`context.route` also answers the service worker's requests in Chromium; `request.serviceWorker()` names the sender) with the defaults of `e2e/fixtures.ts` (`routeApiDefaults`: 404 problem, setup status, empty home, payment details, and the check that nothing else under `/api/donations/payment-` is asked for), so an unmocked call fails the test through its console error; a spec routes only on the context (lint refuses `page.route` there, and the fixture's `page` rejects `route`, `unroute` and `routeFromHAR`, so a shared helper handed the page fails too, because a page route never sees a worker's request; helpers that take a `RouteTarget` take the context, `serveReceiptKeys(context)`), and routing makes Chromium bypass its HTTP cache, so these tests cannot show what the browser keeps by the cache headers (immutable chunks, `stale-if-error`): those are the headers' probes (`probe-asset-caching.mjs`). The fixture fails a test on any console error of a page or a service worker, an uncaught error of a page and a `securitypolicyviolation` of a document, each recorded as `<kind>: <text> (<URL>)`; `test.use({ allowedConsoleErrors: [/…/] })` allows the listed texts (matched against `<text> (<URL>)`), with the reason beside it, and `browserProblems.expectOne(/…/)` names a problem the test causes on purpose, which must then be recorded (waited for up to 5 s) and is taken off the list. Playwright reports neither a Content-Security-Policy violation inside a worker nor a service worker's uncaught error, so the fixture attaches over CDP to every service worker of the context (a browser session: `Target.setDiscoverTargets`, `attachToTarget`) and to the dedicated and shared workers of each page (`Target.setAutoAttach`) and records their violations (`Log.entryAdded` of source `security`) and the service worker's uncaught errors (`Runtime.exceptionThrown`) with the worker's address; a dedicated worker's uncaught error comes as the page's `weberror`. It offers `swReady()` (waits up to 10 s for `navigator.serviceWorker.ready` and up to 5 s for the worker's `clients.claim()`, reloads once only when the worker still does not control the page, fails if it still does not, waits up to 20 s until every file of the prefetch group in `ngsw.json` is in the Cache Storage, and returns once the page has no request in flight for two frames, `e2e/settled.ts`), `goOffline()` and `goOnline()` (`context.setOffline` cuts the network, and a context route registered at that moment aborts every request, because routes otherwise keep answering offline; a route a test adds later still answers), `idbDump()`, `cacheDump()` (cache name, path and query of each entry), `storageDump()` (local and session storage, cookie names, database and cache names), `virtualAuthenticator` (CDP `WebAuthn`, CTAP 2.1 platform authenticator with resident keys, user verification and PRF), the worker option `cameraShows` (a QR text drawn by the app's own encoder into a Y4M frame for `--use-file-for-fake-video-capture`, the camera permission granted; `test.use` at the top of a file of its own, because it starts its own browser) and the option `displayMode` (`'standalone'`, as an app installed from Chrome: an init script answers exactly `(display-mode: standalone)` with `matches: true` and `(display-mode: browser)` with `false`, every other query, combined or negated ones included, keeps its real answer, and CSS `@media (display-mode: …)` is not stubbed; `'ios-home-screen'` also sets `navigator.standalone`; Playwright can neither install an app nor emulate `display-mode`). `pwa-fixtures.spec.ts` plants each kind of problem (a planted inline script is refused by Trusted Types before its source is checked; the planted workers are registered from the marker page, which has no app and so no site policy, under a `default` policy the test creates there) and proves the fixture records it as expected (an unexpected console error and an expected problem that never comes as `test.fail`) and proves each dump, `service-worker.spec.ts` proves with the app's own worker (asked through `CHECK_FOR_UPDATES` messages) that nginx serves its files and the manifest uncached, that it controls the page, caches only public answers (a donor answer's canary never lands in the cache) and asks the network itself, that `setOffline` alone keeps routes answering it and going back online reaches the network again, that a route never opened renders offline and with the server down, that a tab whose chunks are all gone still opens a page, that the server's switch turns it off and empties its caches, that a ready version waits while a form is half-typed and loads at the next page, reloads at once before the first touch and that a file of the tab's version gone from the server reports `sw-unrecoverable` and reloads, and that a removed hashed chunk answers 404; `boot-guard.spec.ts` (with Playwright's clock) that a start that never comes reloads once, then shows the panel, which clears the site and reports `boot` once at the next good start; `payment-route.spec.ts` that the worker serves a reserved payment at `/platba.spayd` itself, once, and refuses a payment written into the address and that Otevřít v aplikaci banky on a phone that cannot share the file opens it from the worker with nothing reaching the server; and `camera.spec.ts` and `device-capabilities.spec.ts` prove the fake camera through `/overit`, the PRF results and the standalone stub through the error report's `display` (read from the media query). `app-launch.spec.ts` proves that the app opened from an iPhone's home screen starts signed out on the home page with no dialog and no focused field, and that nginx serves every launch image the page links as a PNG. WebKit and Firefox over `e2e/pwa/` are the nightly's (3.14).
- A drawn receipt PDF is tested by what it says and does, read back with `features/donations/receipt-pdf/testing/pdf-reader.ts` (pdf.js in Node: text per page with artifacts apart, links, the structure tree, a raster for jsQR); `src/testing/receipt-assets-setup.ts` hands specs the theme fonts, the logo and the v2 receipts; e2e downloads read the saved file the same way (`e2e/receipt-pdf.spec.ts`). The certified text is the shared case `shared-cases/receipts/v1/printed.json` (only the browser runs it since 1.10).
- Test behaviour, text and accessibility, never style values.
- Keeping the suite fast: e2e runs against the production bundle, the code nginx serves, because the dev server compiles again for every run and is slower per page; no spec relies on dev mode (the suite reads no console). CI runs 3 workers with `fullyParallel`, so every test stands alone: no state shared between tests, no order dependence, each mocks what it needs. A test that fails only sometimes is a race in the app or the test: reproduce it, fix it test-first, never retry it away (`failOnFlakyTests` stays). A browser service the headless shell lacks (the password manager, passkeys) is stubbed with `page.addInitScript`, never left to answer on its own. Playwright needs Chromium's headless shell and WebKit (`npx playwright install --with-deps --only-shell chromium webkit`). The project `chromium` runs every journey at desktop size; the project `iphone` (WebKit with the `iPhone 15` descriptor, plan slice 1.12) runs the receipt PDF, `/overit`, Přispět and authenticator journeys and the Trusted Types refusals (`receipt-pdf`, `verify-receipt`, `donate-qr`, `second-factor`, `security-headers`; WebKit enforces Trusted Types as Safari 26 does) at phone size, so the helpers of `e2e/donor-session.ts` reach the account sections through the account sheet (`openAccountItem`) when the viewport is at most the `nav` breakpoint and the side panel is not rendered, and the tabs through `openSection`; a test that cannot run in WebKit skips itself with `test.skip(({ browserName }) => browserName !== 'chromium', reason)` and its reason names what the device checklist covers instead (the clipboard permission, the drawing-time bound). What WebKit in Playwright cannot show (a real share sheet, Files, the camera, printing) is Jakub's device checklist.
