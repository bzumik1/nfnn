# Testing rules: regression against v2

The general rules (TDD, given/when/then naming) are in `testing.md`. How the recording, the transcripts, the comparison and its CI jobs work: `docs/system-overview.md` "Regression against v2 and shared cases"; the commands to record or extend the baseline: skill `regression-baseline`.

## Regression against v2
- `regression/v2/` is v2 as recorded at the commit in `regression/v2/BASELINE_COMMIT` (#201), which never changes. Only fictional fixtures under a fixed clock go in; the repository is public.
- Recording: `API_TRANSCRIPTS=record ./gradlew acceptanceTest --rerun` writes `backend/build/api-transcripts/`; it refuses to start with a mail, app, Spring secret, secret setting or server-generated secret in the environment (`ApiTranscriptsTest`, `RecordingEnvironmentTest`). A scenario whose two recordings differ is not deterministic: fix it at its source (a clock, an order, a random value), never by masking more (`compare-recordings.mjs` on every push to `main`); a list joins `UnorderedTie.V2` only when shown to change order between two recordings. The test JVM's zone, locale and charset are pinned in `build.gradle.kts` (`RecordingEnvironmentTest`); a change to the pin is checked again with two recordings compared by `diff -r`.
- Test inventory: `./gradlew test` for the backend, then in `frontend/` `npx ng test --watch=false --reporters=json --output-file=$PWD/test-results/inventory-vitest.json` and `npx playwright test --list --reporter=json > test-results/inventory-playwright.json`, in `mcp/` `npx vitest run --reporter=json --outputFile=test-results/inventory-vitest.json`, then `node scripts/test-inventory.mjs` (`--out=<file>` anywhere but the baseline commit).
- A baseline file is never regenerated to get a check green. A PR never edits `regression/v2/api/` or `regression/v2/test-inventory.json`; an existing file in `regression/v2/receipts/` or `regression/v2/screens/` never changes and is never deleted, and an entry of `screens/manifest.json`, `receipts/digests.json` or `receipts/refusals.json` stays as recorded, including those added after the baseline once they are on `main` (`compare-v2-baseline.mjs`). A new sample or screen state comes only from a checkout of the baseline commit, as a `baseline-addition` with its patch under `regression/v2/additions/` (skill `regression-baseline`); an existing patch never changes.
- Every PR that changes recorded behaviour declares it in `regression/v2/changes/<slice-or-PR>.json`, one file per slice or PR. Each entry names `kind`, `reason` (the decision) and `contract` (the contract or overview section) and starts every pattern with its literal anchor, `*` only after it. Kinds: `status`, `headers`, `body`, `request`, `removed` and `added` take `path` (a request template `METHOD /api/<context>/…`, `/actuator/`, `/.well-known/` or `/oauth`, `#n` optional) and `scenario` (`<context>/<feature>: …`; `removed` without `path` is the whole scenario); `body` and `headers` an optional `field` (a JSON path glob from `$`, or a header name), `added` a `field` or a mail's `subject`; `mails`, `logs` and `log-field` take no `path`, `mails` a `subject` (required in a file the PR adds or changes), `logs` a `line` (the v2 line without its level, from the logger name), `log-field` a `line` (the exact shape of the new kind of line as the report printed it, without `*`); `retired` takes `suite`, `test` and `replacement` (a test id of the inventory); `shared-case` takes `caseFile`; `baseline-addition` takes `file`, `recordedFrom`, `patch` and `record`. The full grammar and an example are in the overview; `compare-v2.mjs` stops with exit 2 on an invalid entry. Against `main` an added mail, response field or response header needs an `added` entry, a test `main` has and the fresh inventory lacks a `retired` entry with its `replacement`, and a changed shared case its `shared-case` entry (`testing-shared-cases.md`). An unused declaration in a file the PR adds or changes fails.
- A new or changed log line (`logs`, `log-field`) also carries `security: {"approvedIn": "PR #<number>, Jakub <YYYY-MM-DD>", "fields": {"<slot>": "what it holds"}}`, written only once Jakub approved it (`security.md`, Logs), naming every slot of the line; a line whose every slot is closed names the standing approval, `PR #PRNUM, Jakub 2026-11-14`.
- The log gate fails every recorded line that holds `@`, a fixture alias or full name, a capitalised word the transcripts record for a person or an address, a masked value, an account number or an IBAN: fix the log line, never allow-list it. A recorded word that is no personal data is handled by renaming the fixture value or by adding it to `COMMON_WORDS` in `compare-v2.mjs` with its reason here. Today: `Nová`, `Nové` and `Nový` belong to the foundation's own name and street; `Most` is a fixture city and also an English word, kept rather than renamed because renaming it would change the recordings against v2 (the erasure placeholders `Vymazaný` and `Vymazáno` of `ErasedPersonalData` are left out too).
- Hygiene (`regression/BaselineHygieneTest` over `regression/` and `shared-cases/`; the list of what it refuses is in the overview): a change that brings a new kind of secret teaches it to `TranscriptNormaliser` as a masked value, field or shape, refuses its environment name while recording (`ApiTranscripts`), and adds a hygiene rule with a planted case that fails, all in the same PR (`security.md`, Secrets).
- Screens: a slice proves "screenshots equal" against its merge base (`npm run screens:compare` in `frontend/`), not against v2. A page may differ in up to 0.2 % of its pixels, an element shot (the QR codes and bank details) in none, and a changed size always counts; a digest that differs from the v2 manifest means comparing pixels, never recording again. The `visual` job fails on a differing or removed shot that the description's `Vzhled se mění: …` line does not name (by route, state or shot); declare only what the slice means to change, because a difference it did not mean is a bug. A state v2 did not have goes into `SCREENS_SINCE_V2`, never into a manifest.
- Connector shapes: `mcp/test/backend-shapes.spec.ts` fails on a backend call of `mcp/src` without a transcript, and on a fake-backend answer (`test/fake-backend.ts`) with a status, field or type no recorded answer of that call has; a field recorded only as `null` takes another value only when `RECORDED_ONLY_AS_NULL` lists it with its reason. A call recorded only since v2 needs an `added` declaration.
- CI: paste the `compare-v2` report (job summary or artifact `srovnani-s-v2`) into the PR under "Srovnání s v2". When `main-recording` fails because no push run of the last commits on `main` keeps its recording, re-run the push run of `pr-check.yml` on the newest `main` commit (Actions, PR check, Re-run all jobs), then this PR's check.
