# Testing rules (TDD, given/when/then)

Write the test first, watch it fail for the right reason, make it pass with the smallest change, refactor green. Every behaviour has a test at the lowest level that can prove it.

## Backend
| Level | Tool and place | Rules |
|---|---|---|
| Unit | JUnit 5 + AssertJ + Mockito, `src/test/java/.../<context>/<layer>/` | Name `should_<expected>_when_<action>[_given_<state>]` plus `@DisplayName("Given X, when Y, then Z")` on every test (`architecture/TestNamingRulesTest`); a shared setup may be a `@Nested @DisplayName("Given …")` class whose tests read "when …, then …". AssertJ for assertions (MockMvc's `jsonPath` matchers excepted). Mockito for ports, framework collaborators (`ApplicationEventPublisher`, `JavaMailSender`, `TaskScheduler`) and the collaborating service of the class under test; never for aggregates, entities or value objects: build those with the fixtures (`Donations`, `Receipts`, `BankPayments`, `QrCodes`). Mockito loads as a `-javaagent` from `build.gradle.kts`, not by self-attaching (JDK 25 warns, a later JDK refuses) |
| Acceptance | Cucumber, `src/test/resources/features/<context>/<use_case>.feature` (English Gherkin), glue in `<context>/cucumber/`, shared steps in `cucumber/` | One feature per use case; scenarios go through HTTP with `cucumber/ApiClient`; suite `cucumber/AcceptanceTests` glues `cz.novanadeje.app`; `CucumberSpringConfiguration` boots the app with Testcontainers PostgreSQL and `TestSupportConfiguration`. One area: `CUCUMBER_FILTER_TAGS=@<tag> ./gradlew test --tests "*AcceptanceTests"` (`-Dcucumber.*` does not reach the test JVM). Every feature carries the tag of its context folder (`@contact`, `@content`, `@donations`, `@donors`, `@operations`; `FeatureContextTagsTest` fails otherwise), and the connected applications also `@connected-apps`; a tag no feature carries runs nothing and still passes, so check the report's counts (or add a temporary `@wip`). A new feature carries its context tag |
| Integration | `@SpringBootTest` or JPA slice + `TestcontainersConfiguration` | Real PostgreSQL 17 only, never H2; pin the scheduler properties (`CLAUDE.md` Gotchas); schema tests in `shared/infrastructure/schema/` (every foreign key indexed, new changelogs over baseline data, `backend.md` Persistence) |
| Architecture | ArchUnit, `architecture/` | A new invariant gets a rule; rules fail on an empty match |

Test support:
- External ports have fakes in `support/`, registered `@Primary` by `TestSupportConfiguration` (`FakeFioClient`, `RecordingMailSender`, `SynchronousBankImportRequests`, `FakeClientMetadataSource`, `FakeMailServerProbe`, the `Recording…` timers and announcers); a new port adds its fake there. `MailContents` reads sent mail; `FioMovements` builds bank movements.
- `CommonStepDefinitions.isolateScenario` (`@Before`) truncates every table and restarts sequences (`DatabaseCleaner`; receipt numbers start at `000001`), clears mail, resets the fake Fio client and advances `MutableClock` a day. `Given today is {date}` sets the clock, and an `@After` in `FioImportStepDefinitions` moves it forward again so tokens and rate windows never go backwards; `DonorSessions` signs a donor in again after the clock expired the token.
- `FakeFioClient` refuses history older than 90 days until `unlockHistory()` and throws on every bookmark call (`transactions().sinceBookmark()`, `bookmark().moveAfterTransaction/moveToDate`), so `/last/` can never pass.
- In tables `{Jana}` is Jana's variable symbol (`ScenarioDonors`); `{date}` is ISO (`ParameterTypes`). Each scenario sends from its own client address (`X-Forwarded-For`, trusted by the backend); `When the following requests come from another client address` switches; `When the following requests come from the client address {string}` sets a fixed one, safe because `isolateScenario` moves the clock a day forward, past every limit window.

A new feature covers: happy path and each rule as scenarios; validation and problem types; 401 without token and 404 for another donor's resource; rate limits; time boundaries with `MutableClock`; scheduler on and off; a repository test for every derived or hand-written query; a rendering test per new template; `cs` and `en` texts for every new key.

## Frontend
- Vitest specs beside the code (`name.spec.ts`): `describe('Given …')` → `it('when …, then …')`; nested `describe('when …')` with `it('then …')` (or `it('and …, then …')`) when outcomes share a setup. TestBed with `provideHttpClient()`, `provideHttpClientTesting()` (`http.verify()` in `afterEach`), `provideRouter([])`; drive the DOM (events, `fixture.whenStable()`) and assert visible text and ARIA, not internals; fixtures in `*/testing/` (excluded from the app build); `src/test-setup.ts` polyfills `<dialog>` for jsdom and `src/test-providers.ts` (the `providersFile` in `angular.json`) gives every TestBed `LOCALE_ID` `cs`.
- Playwright in `e2e/` by user journey, same naming (`test.describe('Given …')`, `test('when …, then …')`). Nothing may reach a backend: `npm run e2e` builds the production bundle and serves it on :4200 with `scripts/serve-dist.mjs`, which answers like the frontend nginx (`index.html` for app routes, 404 for a missing file) and proxies nothing, and specs import `test` and `expect` from `e2e/fixtures.ts` (lint refuses them from `@playwright/test`): its automatic fixture answers every `/api` request no spec mocked with a 404 problem and serves the setup status and an empty home, and each spec mocks the calls its journey needs (`mockDonorApi` in `e2e/donor-session.ts` for donor and admin pages). CI fails a test that passed only on a retry (`failOnFlakyTests`); with `E2E_DIST` set it serves that folder without building (CI, after its build steps), with `E2E_BASE_URL` set it tests that server and starts none, and locally it reuses a server already on :4200 (`npm start` while editing). `signIn` at 1280 px (the header button is hidden on phones), resize after; downloads via `page.waitForEvent('download')`; `accessibility.spec.ts` runs axe with WCAG 2.2 AA tags, so a new page or dialog gets a case there.
- Test behaviour, text and accessibility, never style values.
- Keeping the suite fast: e2e runs against the production bundle, the code nginx serves, because the dev server compiles again for every run and is slower per page; no spec relies on dev mode (the suite reads no console). CI runs 3 workers with `fullyParallel`, so every test stands alone: no state shared between tests, no order dependence, each mocks what it needs. A test that fails only sometimes is a race in the app or the test: reproduce it, fix it test-first, never retry it away (`failOnFlakyTests` stays). A browser service the headless shell lacks (the password manager, passkeys) is stubbed with `page.addInitScript`, never left to answer on its own. Playwright needs only Chromium's headless shell (`npx playwright install --only-shell chromium`).

## Connector (`mcp/`)
- Vitest specs in `mcp/test/*.spec.ts`, same naming (`describe('Given …')` → `it('when …, then …')`); the backend is `test/fake-backend.ts`, never a real one.

## Logic on both sides
- A computation the backend and the frontend both perform (local first, `backend.md`: the administration's overviews and totals, receipt data formatting, the verification QR data the backend signs and the browser checks) is specified once as shared test cases, inputs and expected outputs in one data file, and the backend and the frontend suites both run every case (Jakub 2026-10-28). A change to the computation changes the cases first, so neither side can pass with its own idea of the result.

## Regression against v2
Plan v3 is checked against v2 as captured from `70e9233` (tag `v2-baseline`): `regression/v2/` holds the API transcripts and the test inventory, `shared-cases/<topic>/*.json` the cases both sides run (`{source, logic, cases: [{name, input, expected}]}`). Only fictional fixtures under a fixed clock go in, so the tag regenerates every file byte for byte; the repository is public, and `regression/BaselineHygieneTest` fails on an id (a passkey's user handle in base64url too), a JWT, a random secret that no backend source spells out, an unmasked refresh cookie, an e-mail address that no backend source uses outside `example.cz`, `.com`, `.org`, `.net` and the reserved `.example`, or the real signatory's name (the receipts' production default).
- Transcripts: `API_TRANSCRIPTS=record ./gradlew test --tests "*AcceptanceTests"` writes `backend/build/api-transcripts/<context>/<feature>.json` (`cucumber/transcript`). Per scenario (`name #n`): every `ApiClient` call keyed `METHOD /path/{id} #n` (path and query, the sent `Authorization`, `Accept-Language`, `Cookie` and similar headers, the body with fields sorted; the status, every response header but `Date`, `Content-Length` and the connection ones, as a string or, sent several times, an array; the body as JSON, text, a PDF's pages and text, or a binary's size and SHA-256), the mails sent (addresses, subject, text part, SHA-256 of the HTML part, attachments) and the `cz.novanadeje.app` log lines as `LEVEL logger: message [Exception]`. Normalised: ids `<id:n>` by first appearance in the scenario (a passkey's `userHandle` and options `user.id` in base64url too), JWTs `<jwt>`, random mixed-case secrets of 32 or more characters `<token>` (CamelCase names stay), secret fields (`password`, `secret`, `otpauthUri`, tokens, codes) and cookie values `<secret>`, a cookie's `Expires` `<time>`, variable symbols `<vs:Alias>` (`<vs:n>` without an alias), the setup code `<setup-code>`, a recovery code `<recovery-code>`, the receipts' default signatory `<signatory-name>`. What v2 does not fix is settled: mails and log lines are sorted with ids blanked, because asynchronous listeners send and log in any order; list items stamped with the same instants are sorted by content, because v2 orders them by random id bits; object fields are sorted before ids are numbered, because v2 writes some answers from maps whose order changes per JVM; field `errors` are sorted; the diagnostics and the thread dump keep only their shape, and the modification times of log and backup files are `<file-time>`; a PDF keeps its text, not its bytes. While recording every scenario starts at `ApiTranscripts.RECORDING_CLOCK` instead of one day after the previous one, so a transcript does not depend on which scenarios ran before it. The baseline copy is `regression/v2/api/`.
- Golden cases: `regression/QrGoldenCasesTest` asks v2 for every case of `shared-cases/qr/payment.json` (through `GET /api/donations/payment-qr`) and `totp.json` (through `QrCodeEncoder`) and fails when the SPAYD text or URI, the error correction, version, mode, ECI header, mask or matrix differs; it also checks ZXing's encoder against the production matrix and decodes it back. `GOLDEN_FILES=write ./gradlew test --tests "*QrGoldenCasesTest" -PnoCucumber` rewrites them, only for a change that is meant and reviewed.
- Test inventory: `node scripts/test-inventory.mjs` reads the backend JUnit XML (`./gradlew test`, Cucumber scenarios included), `frontend/test-results/inventory-vitest.json` (`npx ng test --watch=false --reporters=json --output-file=$PWD/test-results/inventory-vitest.json`), `frontend/test-results/inventory-playwright.json` (`npx playwright test --list --reporter=json > test-results/inventory-playwright.json`) and `mcp/test-results/inventory-vitest.json` (`npx vitest run --reporter=json --outputFile=test-results/inventory-vitest.json`), and writes `regression/v2/test-inventory.json`: every test name per suite, sorted, a repeated name with `#n`.
- A baseline file is never regenerated to get a check green: a slice that changes recorded behaviour says so, from 0.3 in `regression/v2/changes/<slice>.json` with the reason and the contract section.
