- `app.ts` renders first `.status-bar-tint`, a fixed strip of `--color-accent` 12 px high at `top: -7.5px` (4.5 px of it on screen), at opacity 0.12, `pointer-events: none` and `aria-hidden`, above everything but the top layer (`z-index: 1000`), so Safari on the iPhone gives its status bar the site's blue on every page (Jakub 2026-10-30). Safari 26 ignores `<meta name="theme-color">`: WebKit (`LocalFrameView::fixedContainerEdges`) hit-tests the middle of the top edge 4 px inside the viewport, ignoring `pointer-events`, walks up to the first fixed or sticky box at least 90 % as wide as the viewport and takes its plain `background-color` as the bar's colour; it skips a box with `visibility: hidden` or opacity under 0.1, one 10 px or thinner, and a box with `backdrop-filter`, and a fixed box without a colour (the transparent `nav` over the photo) is sampled once from the pixels under it and kept, which gave a white bar while the photo was still loading. It samples the top edge only until the visitor scrolls or touches the page. The geometry and opacity are those limits with a margin, and `e2e/status-bar.spec.ts` checks them on the public pages and the donor overview; then `app.ts` renders `<router-outlet />` and the sign-in dialog while `LoginDialogService.isOpen()` (Back closes it, and goes back a step first from the code from the app and from the recovery by payment, through `DialogHistory`; a sign-in with `returnTo` hands its entry over to that page, the privacy policy link in the registration replaces it) (re-created on every open so panels start clean, except a half-filled registration that `LoginDialogService` keeps without its password until a sign-in or a sent registration; its "Přihlášení / Registrace" switch carries `aria-pressed` and shows only on those two starting steps). `app.config.ts`: `provideRouter` with `chunkLoadRecoveryFeature` (`withNavigationErrorHandler` handing every navigation error to `ChunkLoadRecovery`, below) and `withInMemoryScrolling` (anchor scrolling for `routerLink="/" fragment="o-nas"` links; the home sections carry Czech ids without diacritics: `uvod`, `o-nas`, `projekty`, `aktuality`, `prispet`, `kontakt`), `provideHttpClient(withXhr(), withInterceptors([authInterceptor]))` (`appHttpClient`; XMLHttpRequest because the fetch backend reports no upload progress, which the backup upload of the first setup shows), session restore on start.
- `core/reload/` and `core/navigation/`: `reload-guard.ts` (`ReloadGuard.claim(reason)`, `ReloadReason` `'chunk-load'`): one automatic reload per reason and 60 s (`RELOAD_WINDOW_MS`), the time kept in `sessionStorage` under `nfnn.reload.<reason>` (reached through the `SESSION_STORAGE` token); when the storage cannot be read, written or read back it allows none, so a tab can never reload in a loop. `chunk-load-recovery.ts`: `isChunkLoadError(error)` recognises a failed dynamic import by the browsers' messages (Chromium and Firefox "dynamically imported module", Safari "Importing a module script failed", the MIME-type refusals); `ChunkLoadRecovery.handleNavigationError` sets `failure` (`{ url, initial }`, `initial` while the router has shown no page yet, `Router.navigated`), kept until the next successful navigation, and loads the page that was asked for from the server (`ExternalNavigation.loadFromServer` of the navigation's URL) only when the browser is online (`Connectivity.isOffline()`, `navigator.onLine`), `ChunkProbe` says the reload would land and the guard allows it; `failure` is set before that load, so a browser that stays on the page (a cancelled unload) still shows the offer; `reload()` is the visitor's own reload of it. `chunk-probe.ts`: `ChunkProbe.reloadWouldLand(error)` asks the server with `fetch(…, { method: 'HEAD', cache: 'no-store', signal })` for the chunk the error names (a same-origin `.js`/`.mjs` address in the message), aborted after 4 s (`PROBE_TIMEOUT_MS`), and answers yes, when nothing redirected the request, for a 404 or an HTML page at the chunk's own address (a deploy), or, when the message names none (Safari), for an HTML answer of `/`; another answer, a redirect, a rejected or aborted request (the network is gone or hangs while `navigator.onLine` still says online) is no, so the recovery only offers the reload. `handleNavigationError` sets `failure` before it asks, counts the router's `NavigationStart` events and ignores an answer that comes after another navigation started. It sees only router navigations: a failed `import()` outside the router, a `@defer` block or a worker gets `ChunkLoadRecovery.handleImportFailure` in 1.9, which offers a reload and never reloads by itself (Phase 0 gate, J-m1). `ExternalNavigation.loadFromServer(url)` goes there with `location.assign`, or, when only the fragment differs from the current document (`/#prispet` on `/`), which `assign` would treat as a jump within the page, replaces the address with `history.replaceState` and reloads. ## Shared UI (`shared/ui/`)

- `form-field/`: `<app-form-field label [hint] [messages]>` around one control marked `appFormControl` (needs `id` and `ngModel`); renders `<label for>`, the hint and the message for the first error key (or the error's own text when `messages` has no entry for it, as the server's `{ server: message }`), sets `aria-invalid` and `aria-describedby` once touched or submitted (touched during a pointer press only from `pointerup` or `pointercancel` on, so a message that appears on the blur cannot push the submit button away before the click; a message already shown stays during a press); `form[appFocusFirstInvalid]` focuses the first invalid control on submit; `server-errors.ts` `placeServerErrors(form, errors, controlNames)` puts the field errors of a 400 problem on their controls (touched, cleared by the next edit) and hands back those without a field. Control look is the global `.form-control` in `src/styles/_form-controls.scss`; components only space fields.
- `password-reveal/`: eye button "Zobrazit heslo" (`aria-pressed`, `aria-controls`) switching the input between `password` and `text`; every password field uses it.
- `live-notice/`: `<app-live-notice [notice]>` takes a `Notice` (`{ kind: 'status' | 'alert', text }` or `null`) and keeps a `role="status"` and a `role="alert"` region rendered, showing the text as `.ui-notice--status` or `--alert` in the matching one, so a screen reader announces it; every admin page's action line uses it.
- `copy-button/`: `<app-copy-button [value] what="číslo účtu">`: "Kopírovat" plus the hidden `what` (an optional `label` replaces both with a visible label of its own, as "Zkopírovat zprávu pro technika"); says "Zkopírováno" for 2 s and in a `role="status"` line; a visible sentence when the browser refuses.
- `qr-code/`: `<app-qr-code [matrix] [variant] label>` draws a QR code from the backend's module matrix (`qr-matrix.ts`: `QrMatrix`, `isDark`, `alignmentCentres`) as inline SVG with a 4-module quiet zone, `role="img"` named by `label`. `branded` (default, the payment look chosen by Jakub on 2026-10-23): round dots in `--color-qr-module`, rounded finder squares and alignment marks in `--color-qr-mark`, and over the centre a blue disc with the logo's star (`--color-logo`, `--color-logo-fill`; the matrix must be level H); when the matrix changes it morphs in a wave from the star outwards (kept dots pulse, gone ones shrink, new ones grow in the mark colour and settle to the module colour, ~2.6 s, Web Animations API, nothing under `prefers-reduced-motion`). `plain`: black squares, used for the authenticator link. `pngDataUrl(sidePx)` paints a copy with the token colours and returns a PNG made on a canvas.
- `side-nav/`: `<app-side-nav [groups] label menuLabel [navId]>` renders an area's two-column layout: a sticky panel left (`--side-nav-width` 240 px, under the top bar via `--top-bar-height`, the whole layout at most `--side-nav-layout-max` 1320 px) with a `nav` (`aria-label` = `label`) of `SideNavGroup`s (`{ id, label | null, items: SideNavItem[] }`; a titled group's `ul` is `aria-labelledby` its title, an untitled one has no label) of `SideNavItem` links (`{ path, label, exact?, badge? }`, `routerLinkActive` with `aria-current="page"`, prefix match unless `exact`; a `badge` `{ count, description }` with a count above 0 adds an accent pill with the count (`aria-hidden`) and the `description` as visually hidden text, so the area passes `groups` as a signal-computed value when the count changes), and the projected content (`<ng-content />`, a `router-outlet`) right. Up to 899 px the panel hides behind the pill button `menuLabel` (`aria-expanded`, `aria-controls` = `navId`), followed by the label of the current section (`aria-hidden`, the page's `h1` names it for screen readers; the item whose `path` the address matches, exactly for an `exact` item), the button also carries the badges of the items other than the current section, opens below it as a card and closes on every `NavigationEnd` and on Escape inside it (focus back to the button).
- `radio-group/`: `[appRadioGroup]` on a group of `role="radio"` buttons makes it a `radiogroup` that answers the arrow keys, Home and End by focusing and clicking the next choice; the buttons bind `[tabindex]` 0 for the chosen one and -1 for the rest (sign-in dialog: donor type and sign-in method; password reset: method).
- `markdown/`: `parseMarkdown(text)` (`markdown-parser.ts`) turns a news or project body into blocks (paragraph with line breaks, heading level 2 or 3, list, quote) of inline nodes (text, bold, italic, link, break), the subset in `docs/api-contract.md` ("`content` — public CMS"); a link keeps only an `http(s)`, `mailto:` or site-relative address, everything else, HTML included, stays text. `<app-markdown [text]>` renders the tree with its own elements through a recursive `ng-template` and `{{ }}` bindings (no `innerHTML`), in the prose look (70 ch, serif headings). `<app-markdown-toolbar [target]>` above a textarea: the `role="group"` "Formátování textu" with Tučně, Kurzíva, Nadpis, Odrážky, Číslování and Odkaz, each wrapping the selection or prefixing its lines (a placeholder word selected when nothing was), then focusing the textarea and dispatching `input` so `ngModel` follows; the field's hint says how to format and that the editor's "Náhled" shows the look (the body-only preview under the textarea went with the editors' whole preview, Jakub 2026-10-24). Texts under `ui.markdown.*`; specs beside each.
- `file-button/`: `<app-file-button inputId [accept] [describedBy] [disabled] (chosen)>` is a file choice that looks like a button: a visually hidden `input type=file` and its `<label class="ui-button">` with the projected text (the focus ring of the input drawn on the label); `chosen` emits the `File` and the input is reset, so the same file can be chosen again (the photo in the news and project editors, the signature scan).
- `dialog/`: `<app-dialog labelledBy [wide] (dismissed)>` on a native `<dialog>` opened with `showModal()` (focus kept inside, page inert, focus to the `autofocus` control; Esc, × and backdrop emit `dismissed`; focus returns to the opener on destroy; full-screen up to 480 px). The panel ends with a visually hidden `role="status"` region, rendered with the dialog and empty, which shows `DialogAnnouncer.message()` (`dialog-announcer.ts`, root): while a modal dialog is open the page behind it is inert and out of the accessibility tree, so a message from behind it (the chunk-load bar) is announced only from inside the open dialog; `announce(text)` returns the function that withdraws it, which leaves a later announcement standing. `dialog-history.ts` (`DialogHistory`, root service) gives the sign-in dialog the browser's Back: `open(listener)` pushes one entry for the same address (state key `nfnnDialogDepth`), deferred until a running navigation ends (`router.currentNavigation()` is null), so a guard-opened dialog adds it on the page it redirected to; `showStep(depth)` adds or takes back entries for further steps; Back over its own entry calls the listener's `stepBack()` or `close()`, and a jump past the page closes the dialog and leaves the navigation to the router; `close()` takes its entries back with `history.go(-n)`; `handOver(url)` replaces the top entry with the page a guard-opened dialog was opened for, which the router then replaces again (the router replaces an entry whose address is already the target), so Back from that page returns to the page under the dialog; `release()` forgets the entries without traversing (a link that opens another page in their place with `replaceUrl`), and any imperative navigation forgets them too, so closing later never leaves the page. Its popstate listener sits on `window` in the capture phase and is registered when the module loads, before Angular's `Location` registers its own: Chrome runs listeners on `window` in registration order, and the dialog's own entries must never reach the router, whose same-address `NavigationSkipped` would make `public-shell` move the focus to the page heading. `testing/fake-dialog-history.ts` records the calls for specs.

Web byl mezitím možná aktualizován nebo vypadlo připojení. Zkuste ji načíst znovu." After a later navigation, a bar over the page (`.chunk-load-bar.ui-notice--alert.ui-notice--floating`, fixed at the bottom, at most `--content-max` wide) whose button "Načíst znovu" takes the focus and is `aria-describedby` the message, so the message is announced once, with the focus move; the bar is no `role="alert"`, because an alert would announce the same text again and a screen reader that cuts speech short on the focus move could drop it; when the focus cannot reach the button (an open modal `dialog` makes the page behind it inert and leaves it out of the accessibility tree, so no region of the bar would be announced either), the bar hands the message, read from its own rendered text so the one i18n id `layout.chunk-load.message` serves both, to `DialogAnnouncer`, whose region inside the open dialog announces it, and withdraws it when the bar goes; the notice itself renders no status region, so a page's own status region stays the only one; while it shows, `:root` carries `has-floating-notice` and `--floating-notice-height` (measured, kept by a `ResizeObserver`; the themes set it to `0rem`), which add that room below the page (the public footer's own `padding-bottom`, so its colour reaches the bar, or `body`'s on a page without it) and to `scroll-padding-bottom`, and a `focusin` listener scrolls a control the bar would hide above it in the next animation frame, after a left field has added its error line (Chromium does not scroll an element that is already in the viewport behind a fixed bar), leaving controls in an open `dialog` alone, so the bar never covers the end of the page or the focus (WCAG 2.4.11).
