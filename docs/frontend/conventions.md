# Frontend conventions in detail

The full text of the frontend rules as they stood on 2026-11-06, with every list of files, tokens, blocks and checks, kept here when the rules were cut to their constraints (`.claude/rules/frontend.md`, `.claude/rules/testing-frontend.md`). A change updates the rule's constraint there and the description here.

## Angular 22 (standalone, zoneless, signals)
- Components: flat names `hero.ts/.html/.scss`, class `Hero` (no `Component` suffix), selector `app-*`, no `standalone: true` (default), no NgModules. Change detection is OnPush (Angular 22's default; the existing components still spell it out, a new one may omit it); never `ChangeDetectionStrategy.Eager`/`Default` (lint rejects it). So a template may read only signals, inputs and what its own events change: state that arrives otherwise (the forms API, a subscription) goes through a signal, as `appFormControl` turns the control's events into `showsError()` and `errorKey()`.
- State in `signal`/`computed`/`linkedSignal`; `input()`, `output()`, `model()` instead of decorators; `inject()` instead of constructor parameters; a parameterless constructor holds the start-up work (initial load, `effect`, `afterNextRender`, `DestroyRef.onDestroy`); `host: {}` metadata instead of `@HostListener`/`@HostBinding` (lint: `prefer-host-metadata-property`); no `any`; strict TS and templates stay on.
- Templates: `@if/@for/@switch/@defer`; `[class.x]`/`[style.x]` (no `ngClass`/`ngStyle`); import only the directives and pipes used (never `CommonModule`); logic in the class.
- Forms: template-driven `ngModel` inside `<app-form-field label hint [messages]>` with `appFormControl` (needs `id` + `ngModel`) and `form[appFocusFirstInvalid]`; the field shows its own first error after touch or submit (`aria-invalid`, `aria-describedby`), a field left by a pointer press shows it only when the press ends, so the message cannot move the button away from under the pointer, and a required field the visitor only passed through without typing says nothing until submit (experts' decision for #359: on iOS the tap ends before the focus moves, so the message jumped the form under the finger); every text field names its return key with `enterkeyhint` (`next` before another field, `go` or `send` on the last; a textarea keeps its new line), and with the on-screen keyboard open `next` moves to the next field unless the form is already valid; a form-level alert only for what no field owns (passwords differ, an API refusal). Signal Forms are stable in Angular 22 but not used here: switching means migrating `form-field`, `appFormControl` and every form at once, so only by decision.
- Local first (`backend.md`): compute and render here whatever the data already in the browser allows; the backend only serves it.
- HTTP and data: one `providedIn: 'root'` service per backend resource, `<name>-api.ts` in its feature folder (sign-in and account calls: `core/auth/auth-api.ts`), relative `/api/...` only, every id or slug in a path through `encodeURIComponent`, so an address such as `/aktuality/..%2F..%2Fdonors%2Fme` cannot send the token to another API path, DTO interfaces mirroring `docs/api-contract.md`; a component calls it and `subscribe`s into signals, as every existing page does (no `httpResource`/`rxResource` piecemeal). The donor's gifts are the one read that may come from the device: Moje dary, Přehled and Potvrzení read them only through `DonorDonationsRepository` (`features/donations/device-copy/`, 2.15), which answers from the device copy while it agrees with its summary and from `donations-api.ts` otherwise, and reaches the copy only through `DonorCopyLink`; every write, and every other read, goes to the `-api` service. Every call passes `keptPublicAnswersInterceptor` first (`core/navigation/kept-public-answers.ts`: a GET of the public content, the home answer, the news and project lists and pages, a subset of the service worker's same-for-everyone list that its spec pins, is answered from memory when the tab already had it within 10 minutes, and asked again in the background; any write under `/api/admin/content/` forgets them all; a new kept path stays inside that list), then `authInterceptor` (Bearer header except on the same-for-everyone answers of `service-worker-bypass.ts`, problem+json Blob parsing, one refresh on `auth/expired-token`) and then `versionInterceptor` (`core/version/`: the app's `Nfnn-App` and `Nfnn-App-Api` on every `/api` call, the server's `Nfnn-Revision` and `Nfnn-Api` read from every `no-store` answer into `ServerVersion`, and while the server speaks another API generation every write but the session refresh, sign-out and receipt status answered locally with the problem `app/update-required`, which the server also answers to a write from another generation; a page that keeps its own failure text recognises the problem, as the contact form and the receipt download do); only the API service of a public endpoint may send its request without the token, with the context `WITHOUT_ACCESS_TOKEN` (`core/auth/auth-interceptor.ts`), and ESLint's `no-restricted-imports` in `eslint.config.js` allows that import only in the files listed there (today `payment-details-api.ts`, the receipt verification's `receipt-keys-api.ts` and `receipt-status-api.ts`, `setup-api.ts` for the setup status the restart wait polls, and `core/connectivity/connectivity-probe-api.ts`, whose probe asks the same status): a new public endpoint that should skip the token adds its service to that list; errors become one line through `describeProblem` (`core/auth/api-problem.ts`). The live stream (`core/live/live-api.ts`, `GET /api/live`) is an `HttpClient` call too, a text stream read through download progress, so it carries the token and refreshes like any call; a page listens through `LiveUpdates.changes(feeds)` and keeps working when no stream is open. Three calls bypass it with a raw `fetch`: `core/errors/error-reporter.ts`, whose browser error report goes with `keepalive` and `credentials: 'omit'`, so it never carries a token, survives the page closing and cannot itself fail through the interceptor into another report; `core/reload/chunk-probe.ts`, whose `HEAD` asks the server for a lost chunk (`cache: 'no-store'`, aborted after 4 s) and is no API call; and `receipt-pdf/receipt-fonts.ts` in the receipt PDF worker, which reads the theme's TrueType files from `/receipt-fonts/` (static files of the build, no API call; a worker has no `HttpClient`). Nothing else calls `fetch`. The HTTP backend is XMLHttpRequest (`withXhr()` in `appHttpClient`, `app.config.ts`, for the whole app): fetch, Angular 22's default, reports no upload progress and `reportUploadProgress: true` under it throws NG02824, while the first setup's backup upload shows a progress bar (`reportUploadProgress`; `reportProgress` is deprecated since 22.0).
- Own history (#431, Jakub 2026-11-06): `core/navigation/own-history.ts`, installed in `main.ts` before Angular, turns every `pushState` into a replace of the browser's one entry of the site and keeps the steps itself (`sessionStorage` `nfnn.app-history`), on every device, so the browser's Back and Safari's swipe leave the site and the site steps back only through Zpět, a dialog's ×, `history.back()` and the swipe of the home-screen app (`edge-swipe-back.ts`, on iPhone and iPad only there). Nothing else may add a browser entry: a full page load inside the site goes through `ExternalNavigation.loadFromServer` or `history.replaceState` + `location.reload()`, never `location.assign` or a plain `href` to a page of the site (content links go through `Markdown`'s router click); e2e steps back with `stepBack(page)` of `e2e/app-history.ts`, and `page.goBack()` is the browser leaving the site. A dialog that hands its entry over to a page (`DialogHistory.handOver`) passes `BackTarget.nextDepth()` as `APP_DEPTH_KEY` in the navigation's state, as the account sheet and the paired payment's sheet in Platby do, so the page's step back, its swipe preview and × of the administration count the handed-over entry.
- Stepping back, one rule for the whole site (both polish teams 12/12, 2026-11-17, after Jakub found the step back inconsistent; the code is brought to it group by group, #1358 first): like a native iOS app, no step without the screen moving under the finger and no movement without a step, so the edge swipe either moves a real screen or does nothing and never jumps. While dragged, the top screen follows the finger 1:1 with no transition over the real previous screen, never blank or black, under the existing `--shadow-page-edge` and `--color-page-dim`; on release it takes the finger's speed (`easingLeavingAt`) and finishes or returns within `--duration-page` on `--ease-page`; a swipe that starts during another transition takes the page over where it is (a running T12 fade finishes at once and the drag starts from the finished page) or is ignored, never a jump. The target is where the visitor came from in the same tab's stack, an open sheet on the same section included (a page or the administration opened from the account sheet steps back into that sheet, which already stands under the leaving page and does not enter again); between tabs the parent stays the target (#394), since switching tabs is no step; Zpět, the swipe, the system step and Esc share the target, the scroll of the previous screen is kept, and focus goes to the control the visitor left by, else the target's heading, and the target's name is announced (no new sentence or i18n id; Zpět stays „Zpět“). Over a modal sheet or dialog the edge swipe does nothing (the sheet closes by its drag down or ×, focus to its opener), except the sections inside a sheet (the account sheet's stack), where it does what ‹ does: the sheet's content follows the finger over its list and the sheet stands. From `nav` up (iPad landscape, windows of 899 px and more) only a real push follows the finger (a detail within the section: article, story, donor card, payment, editor): the content area, clipped at the side navigation's edge and without `--radius-page-card`, while the side navigation and the header stand and are not dimmed; choosing another section in the side navigation is no step, so the swipe does nothing there and the T12 fade stays; a step back the site starts itself (‹, a key, `BACK_NAVIGATION`) takes the T12 fade when pressed with a mouse, a trackpad or a key, and the same pop as the swipe when ‹ is tapped by a finger (decided by the pointer's `pointerType`, not the device, so an iPad with a trackpad fades), while `popstate` (the browser's Back, a mouse button, Safari's own gesture with its snapshot) stays without a transition so two transitions never meet; the flag for a site's own step is set before `history.back()` and cleared at `NavigationStart`, focus moves at the start of the step, not after the fade, and after a step between sections it goes to the side navigation's item the visitor left. Every gesture keeps its one-tap control (‹, ×, Esc); with `prefers-reduced-motion` the page does not follow the finger and the step happens on release, at once or with a short fade.
- Routing: lazy per feature (`<feature>.routes.ts`, `loadChildren`/`loadComponent`); only the routes marked `LOADED_AHEAD` (`core/navigation/tab-preloading.ts`: the public shell, the content routes and the four tab pages) are loaded ahead once the first page has opened, so a tab opens without waiting for its code, and every other page stays lazy (the chunk-load journeys rely on that), `title` via `$localize`, addresses and section ids in Czech without diacritics (`/darce/prehled`, `/sprava`, `/prispet`, `/o-nas#kontakt`; only `/api/...` stays English; a page that moves keeps its old address as a redirect, as `oldSectionRedirect` does for the former `/#…` sections), `/darce/**` behind `donorGuard`, `/sprava/**` behind `adminGuard`, public shell with header and tab bar, unknown paths show `not-found`; nginx answers the app's routes with 200 and every other path that is no file with the same `index.html` and 404 (the map `$app_page` in `frontend/nginx.conf`, kept equal to the routes by `app.routes.spec.ts`: a new route or a renamed one changes its line there in the same PR), and an unknown slug of a detail route with 200, where the page sets `noindex`.
- Formatting is Prettier's (`.prettierrc`: 100 columns, single quotes, Angular parser for templates): run `npm run format` before committing; CI fails on a file it would change.
- Lint is ESLint with angular-eslint (`eslint.config.js`: recommended TypeScript and template rules, template accessibility, `prefer-inject`, `prefer-signals`, `prefer-output-readonly`, `prefer-on-push-component-change-detection`, `prefer-control-flow`, `prefer-self-closing-tags`): run `npm run lint` before committing; CI fails on a finding. `eslint-confinement.js` is the frontend twin of `AdapterLibraryRulesTest`: its table `CONFINED_IMPORTS` names each library or module family with the scopes allowed to import it (`SCOPES`: `app`, `testSupport`, `routes` and the adapters; a narrower scope names the one it lies `within`, which then ignores its files, so every file is in exactly one scope whatever the order of the config objects), refuses it elsewhere statically, as a type or by `import()` of a string or template literal, refuses every `import()` of a computed name outside route files, and with `lazyOnly` allows a library in its adapter only through `import()` (types still pass). ESLint runs with `noInlineConfig` and `ng lint` fails on a warning (`maxWarnings: 0`): no `eslint-disable` directive, since it is a comment (`CLAUDE.md`, No comments); an exception is a scoped config object or a named helper in a file the rule ignores (`e2e/fixed-waits.ts`, `testing.md`, Frontend e2e). `npm run lint` also runs `scripts/eslint-confinement.test.mjs`, which lints an example of every entry in every scope and fails on a scope that matches no file; a new library or adapter adds its entry or scope and its examples there. Two scoped exceptions, both for the native `<dialog>`: `autofocus` is allowed in `*dialog*.html` because the dialog moves focus to it on open, and `shared/ui/dialog/dialog.html` closes on a backdrop click without key events because Esc closes it natively.
- Folders: `features/{content,donors,donations,contact,operations}` mirror backend contexts; `features/admin` holds every `/sprava` page whatever context it calls (a new page: `features/admin/<page>/`, calls in `admin-api.ts` unless the context already has a feature service for both sides, as content's `news-api.ts` and `projects-api.ts`, a route in `admin.routes.ts`, an entry in `ADMIN_SECTIONS`); singletons in `core/`; a behaviour-only piece used twice moves to `shared/ui/` (`form-field`, `dialog`, `copy-button`, `share-button` for the Web Share API with the copy button as its fallback, `password-reveal`, `qr-code`, `avatar` for a person's round portrait or initials, `zoom-viewer` for a photo or QR code opened large and zoomable (`app-zoomable`), `markdown` for content bodies, `side-nav` for the side panel of `/sprava` and `/darce`, `account-username` for the hidden user name of a form that asks for the current password).
- Trusted Types are enforced (`security.md`, Browser): no string reaches a markup, script or script-address sink (`innerHTML`, `insertAdjacentHTML`, `DOMParser`, `script.src`, `importScripts`, `eval`); text goes in through bindings or `textContent`, a worker starts only as `new Worker(new URL('./x.worker', import.meta.url), { type: 'module' })`, which the build turns into `/worker-<hash>.js` and the site's `default` policy (`core/security/trusted-types.ts`, installed in `main.ts`) admits, and a new library is checked for sinks under the e2e suite before it lands.
- No CDN, inline script or third-party resource (CSP rule in `security.md`): fonts, images and scripts come from `public/` or the build, and QR codes are inline SVG drawn by `shared/ui/qr-code` from the module matrix (the saved PNG goes through a `data:` image and a canvas), which the browser encodes itself with `qr-encoder.ts` (no library; the authenticator QR since 1.3, the payment QR from 1.4).
- Web as an app (plan v3 2.4, `docs/frontend-overview.md` `core/updates/`): Angular's `ngsw-worker.js`, registered only by `core/updates/angular-service-worker.ts` (`@angular/service-worker` is confined to it in `eslint-confinement.js`; the rest asks `AppUpdates` through `SERVICE_WORKER_UPDATES`). `ngsw-config.json` keeps the shell and, of the API, only answers that are the same for everyone (`security.md`, Browser): a new cached path joins `ServiceWorkerCachedAnswersTest`'s probes and its list of public handlers, which fail otherwise, and the anchored list of `core/updates/service-worker-bypass.ts`, without which the app sends it with `ngsw-bypass` (every other `/api` request does, because Angular matches a data group URL anywhere in the address). A new version loads by itself, with no button, only at a free moment (`AppUpdates`): before the first touch after the start, at the next navigation, or at once for a new API generation (once per generation and build), never while `DirtyForms.any()`, `RunningWork.any()`, a dialog is open or the app is offline; every form registers through `appFocusFirstInvalid` (its host directive `TrackedForm`), and a form without it carries `appTrackedForm`, so no half-typed text is lost to an update. A reload the app starts by itself goes through `ReloadGuard.claim` with its reason. The app's start address is `/aplikace` (`appEntryGuard`), and the manifest is a theme asset checked by `check-themes.mjs`. The built worker begins with the site's own payment route (`frontend/service-worker/payment-route.js`, prepended by the `postbuild` of `npm run build`, so build with `npm run build`, never `ng build` alone, for anything that ships or runs `e2e/pwa/`): it serves only a payment the page reserved by a message (`LocalPaymentRoute`), once, at `/platba.spayd?id=<id>` on the device, and any other code in the worker is a security change (`security.md`, Browser).
- Receipt PDF: drawn in the browser by `features/donations/receipt-pdf/` in a module worker (`receipt-pdf.worker.ts`, its own chunk); pdfkit only in `receipt-layout.ts`, and that file only in the worker and tests (`eslint-confinement.js`), so no other bundle carries it; the layout takes its colours, type sizes, leading and margins from `ReceiptStyle` and its fonts from the theme (it owns only the geometry of its blocks, as a component owns its structure), and every word from the frozen receipt or the captions passed in.
- Receipt verification (`/overit`, `features/donations/verification/`, `docs/frontend-overview.md`): the proof is read and checked in the browser, with WebCrypto `Ed25519` and, only where the browser lacks it, `@noble/curves` from `noble-ed25519.ts` through `import()` (a lazy chunk); the key list kept in `localStorage` is replaced whole by each trusted list, never merged; a code is read from the browser's `BarcodeDetector` or else jsQR, which only `qr-decoding.ts` imports and only the module worker `qr-decoder.worker.ts` loads (`eslint-confinement.js`), so it is in no page bundle; the camera (`Permissions-Policy camera=(self)`) starts only on the visitor's press and stops on a read, on stop, after two minutes and when the tab is hidden or the page is left; only the exact prefix `https://nfnn.cz/overit#` with digits is accepted, and nothing read is ever opened or navigated to.
- Device copies (`core/device/crypto/`, plan v3 2.13, `docs/security-overview.md` "Device copies"): only WebCrypto and the Argon2id worker; every key imported or generated is non-extractable, the root key lives only in an open `OpenCopy` and is zeroed by `close()`; every record and wrap is sealed with AES-GCM and the length-prefixed additional data of `framed`, so a new kind of record or wrap names its own label and fields there; hash-wasm only in `argon2.ts`, which only `argon2.worker.ts` loads (`eslint-confinement.js`), and the app derives a password key only through `WorkerPasswordKeyDerivation` with its parameters stored beside the wrap; no e-mail, name or user handle in the clear outside an open copy (the registry keeps tags); the core stores nothing itself (lint refuses it every browser store, `scripts/device-crypto-storage.test.mjs`); the PRF input is per device, never per copy, so one passkey ceremony opens every copy; a PRF output never leaves the device, so `PasskeyAuthenticator` keeps sending no `clientExtensionResults`. The store (`core/device/store/`, 2.14) is the only code that keeps a copy: idb only in `idb-device-storage.ts` (`eslint-confinement.js`), every change one transaction, the `DeviceVault` the only writer and reached by the session only through `SESSION_DEVICE` (`device-copies.ts` loads it lazily); a new kind of stored value goes through it, and its tests scan the raw storage for a canary (`testing/raw-scan.ts`).
- Browser storage names (IndexedDB databases, `localStorage` and `sessionStorage` keys, Web Lock and `BroadcastChannel` names) start with `nfnn.` (the older `nfnn-refresh` and `nfnn-session` stay as they are) and are never renamed, because a tab of the previous build and the data a device already holds use them.
- Sessions: access token in memory (`AuthStore`; after a refresh posted to the other tabs over the `BroadcastChannel` `nfnn-session`, never stored), refresh cookie set by the browser, `localStorage` flag `nfnn.donor-session` only says a session may exist (a "Cizí počítač" session keeps it in `sessionStorage` and `PublicSessionIdle` signs it out after an hour without input, plan v3 2.10); the installed app has its own lock, channel and flag (`core/auth/session-jar.ts`) and names its own refresh cookie with `Nfnn-Session: APP` on refresh and sign-out; nothing else adds auth headers.

## i18n
- Czech source: every visible string has `i18n="@@<area>.<page>.<key>"`, the first segment one of `home`, `content`, `donor`, `admin`, `operations`, `layout`, `ui` (follow the neighbouring component); attributes `i18n-alt`, `i18n-aria-label`, `i18n-placeholder`; TS text with `$localize\`:@@id:text\``. Ids are stable, never renamed. There is no translation file yet.
- The source locale is `cs` (`angular.json` `i18n.sourceLocale`, so the build carries the Czech locale data and `LOCALE_ID` is `cs`; specs get the same from `src/test-providers.ts`). Format through the cs-CZ helpers, one place per format, not Angular's locale pipes: `formatMinorUnits`/`formatCrowns` (`donation-amount.ts`), `formatDonationDate`/`formatBankTime`/`formatPragueClock` (`donation-date.ts`), `formatMonth`/`formatMonthRange` (`donation-month.ts`), `formatReportMonth` (`admin/report/report-month.ts`); ICU plurals use the Czech categories `one`, `few` and `other` (`=0` only for a sentence of its own); TypeScript picks a form with `pluralCategory(count)` (`core/i18n/plural-category.ts`, over `Intl.PluralRules('cs')`).
- Czech copy: no vocative or declension of names (show the name alone); sentence case; the donate action is "Přispět"; amounts from the API (hellers) go through `formatMinorUnits(minor)` (crowns typed by a visitor through `formatCrowns`), which gives `1 000` or `1 000,50`, followed by `&nbsp;Kč` in a template and `\u00a0Kč` in TS; dates `15. 3. 2026` and times with a date `15. 3. 2026 8:05`, without leading zeros except the minutes (ČSN 01 6910, Jakub 2026-11-06), the receipt PDF too; the day and month of a date stay together and the year may go to the next line (ÚJČ, ČSN 01 6910; Q13b of both design teams, 2026-11-16, after the largest text at 320 pt broke a date with no-break spaces inside its year): `formatDonationDate` and the date of `formatBankTime` join day and month with a no-break space (U+00A0) and put an ordinary space before the year, the time follows after an ordinary space where the line may break, a date in a short item ("ověřen 17. 10. 2026", a date cell of the administration, a date beside a gift or a connection in the donor's account outside the gifts table) carries `.ui-date` on its inline element and stays whole from `nav` up when it fits, and a range of dates keeps a no-break space before its dash, while the receipt (`formatReceiptDate`: the PDF and `/overit`) keeps the ordinary spaces of its frozen text and shared cases; bank times in Prague time; backend titles and details are shown as they come (already localized). A one-letter word (k, s, v, z, o, u, a, i) keeps the next word on its line by a no-break space (U+00A0: `&nbsp;` in a template, `\u00a0` in `$localize`; team decision M1′, #1486, #1512). The no-break space is required when that word has at most N letters, and before a longer word it may stay wherever the group fits the line. N and its reason are in `frontend/scripts/one-letter-word-limit.json` (`longestWordKeptWithAOneLetterWord`, today 6, `reason`: the intro heading of `/o-nas`, an h2 of the privacy policy at 320 pt and the card title of `/sprava` at 320, 900 and 1000 px are the narrowest lines): the largest number of letters at which the widest such group of the site's texts fits the narrowest line at 200 % text (paragraphs, headings, list items, table headers and cells, `data-label`, `ui-badge` and `ui-pill-button` on a phone 320 pt wide and in the administration's tables 900 and 1000 px wide), measured by `e2e/largest-text.spec.ts` ("Given the longest word a one-letter word keeps beside it…"), which fails when the measurement differs from the file. „1 Kč“ and a number with its unit, IČO with its number and a word with the dash after it stay together; a dash after a bold lead-in name (the list of rights in the privacy policy) may start the next line. Never U+2011 in a label or heading. The lint `scripts/portal-no-break-spaces.test.mjs` (`npm run lint`) checks one way only: every template and `$localize` text under `src/app` must have the no-break space before a word of at most N letters, and before a longer word it accepts either space, leaving the e2e at 200 % to keep a no-break space there from overflowing; it also refuses U+00A0 in a text read only by assistive technology (`aria-*`, `title`, `alt` and the `$localize` texts bound to them). It leaves out, each with its reason in `NOT_CHECKED` and `NOT_CHECKED_KINDS`, the browser tab titles and the lines of the downloaded backup key file, and the texts drawn into the receipt PDF (`*.pdf.*`), which change only with a look sheet and get the rule of their own in #1522. At 200 % text on a phone 320 and 390 px wide no group of a one-letter word overflows its line and no word breaks inside (`keptTogetherTooWide` of `e2e/kept-together.ts` in `e2e/accessibility-keyboard.spec.ts`). At the largest accessibility text (AX5, root 53 px) the check covers only the groups a one-letter word keeps by a no-break space: none of them may reach past the line of the element that holds it (`e2e/largest-text.spec.ts`, `oneLetterGroupsPastTheirLine`); every other overflow at AX5 is tracked in #1583. Only there may the safety net, `overflow-wrap: break-word` set on `html` in `styles.scss` and inherited by every text (it acts only where a line overflows and leaves min-content sizes alone) and on both faces of the busy label (`busy-label.scss`), break a group wider than its line, even a short one; it never permits breaking a word at ordinary enlarged text. Specs compare a component's text through `withOrdinarySpaces` (`src/testing/ordinary-spaces.ts`), so only the lint checks the no-break spaces, and a bold reserve filled from `data-label` keeps the label's width (`boldReservesApartFromTheirLabel`, at 390 and 1280 px).
- Names in running text (#1254, #1306): a button, card, section or choice named inside a sentence stands in Czech quotes („Přidat účet“, „Firma“, „Bankovní účty“) with the full stop after the closing quote; a name that is itself a link (a routerLink such as Moje dary) takes none; an iOS or macOS element is named literally as the system has it („Sdílet“, „Přidat na plochu“, „Soubor“, „Přidat do Docku“); the donor's portal says „v kartě“, never „na kartě“. A device's label inside a sentence comes from `deviceNameInSentence` (`devices-card/device-labels.ts`), whose fallback words are in lower case („Odhlásit neznámé zařízení?“), while the list keeps „Neznámé zařízení“ as its title.

## UI (the look)
- The look is a swappable theme, independent of behaviour (Jakub 2026-10-23, plan `/mnt/project-files/nfnn-ux/oddeleni-vzhledu.md`). The theme owns every value of the look; a component owns only its structure (which grid, flex or order, which widths of its own content, which token for which part). Replacing the theme must restyle the whole site without touching a template, a component's SCSS or any TypeScript.
- A theme is a folder `src/themes/<name>/` with `_theme.scss` (its `@font-face` rules and every token on `:root`, plus at most rules that restyle the `ui-` blocks), its fonts, `assets/` (the files of its look, served at the site root by its build configuration with `output: "/"`: the tab icons `favicon.svg` and `favicon.ico`, `apple-touch-icon.png`, `app-icon.svg`, `launch-icon.svg` (the star without a tile, from which the launch screen and the iOS launch images are drawn), `images/logo.svg` and `images/logo-on-dark.svg`; every theme carries the same file names and none of them is also in `public/`) and `receipt/` (the receipt PDF's TrueType fonts `body.<hash>.ttf`, `body-bold.<hash>.ttf` and `heading.<hash>.ttf` with their licence, made by `scripts/make-receipt-fonts.sh`, which also writes their names into the theme's `--receipt-font-*` tokens; `angular.json` copies them to `/receipt-fonts/`, the control theme's under its configuration; the `--receipt-color-*` tokens are literal `#rrggbb`); `styles.scss` loads it as `@use 'theme'` from the include path, so the build picks the theme: `nova-nadeje` by default, `control` with the configuration `control-theme` (`ng build --configuration=production,control-theme`, `ng serve --configuration=control-theme`). The control theme is deliberately different (teal, system fonts, square corners, 5 px spacing unit) and exists only to prove the swap: CI builds it and `E2E_THEME=control npx playwright test e2e/theme.spec.ts` opens every public page, the sign-in dialog, every `/darce` section and every `/sprava` page and fails on any colour or font of `nova-nadeje` that the control theme does not share. A new token goes into every theme in the same PR: `npm run lint:styles` runs `scripts/check-themes.mjs`, which fails when a theme misses a token the styles use or `nova-nadeje` sets, when a receipt colour is not a literal `#rrggbb` or its text or QR colour falls below 4.5:1 on white, and when a receipt font token names a file that is missing or whose content does not match the hash in its name, or a font sits in `receipt/` that no token names, or a `--receipt-*` token is set outside the theme's top-level `:root` block (a media query would make the receipt depend on the device), when a tab bar colour is not literal or is set anywhere but the top-level `:root` or a `@media` block of `:root`, its labels fall below 4.5:1 (the focus ring 3:1, against the bar and the pill) over a white or a black page, or a solid pill below 3:1 against a solid bar, and when the themes' `assets/` differ, shadow a file of `public/` or a build serves another theme's. A new page gets a line in `e2e/theme.spec.ts`.

- `npm run lint:styles` (in CI) rejects in components a raw colour, font, font size, weight, line height, letter spacing, radius, shadow, a `px` spacing other than a 1 px hairline (`padding`, `margin`, `gap`), a transition duration and a `width` media query. ## UX (how it behaves)
- Offline (plan v3 2.7, `docs/frontend-overview.md` `core/connectivity/`): whether the app is offline comes only from `Connectivity`, which judges the API's answers and its own probe, and trusts the browser only when it says offline (`navigator.onLine` false, which a phone in airplane mode reports while its requests hang; Jakub 2026-11-06), never when it says online; `browserSaysOffline()` serves the error reporter and the chunk-load recovery. Nothing waits on the network when `Connectivity` says offline: a public page shows the service worker's copy at once and is refreshed behind it (`keptAnswerRefreshInterceptor`), and the session restore gives up at once. Every control that needs the server (every submit button, every button without a `type`, every `ui-button--danger` or `--danger-soft` button and every button whose `(click)` reaches a `subscribe`, `firstValueFrom` or `lastValueFrom` through its component's own methods) carries `appNeedsConnection`, and its component imports `NeedsConnection`: offline it stays visible and focusable, `aria-disabled` with the hint "Potřebuje připojení", and nothing is sent; `scripts/needs-connection.mjs` (run by `npm run lint`) fails on one without it, and a control that works offline goes into its `WORKS_WITHOUT_CONNECTION` (a template, or `template#handler`) with the reason; an entry that names no control fails too. A call the check cannot see (a click that hands the work to another service) still gets the directive by hand. The fixed offline pill keeps room for itself through `html.is-offline` and `--offline-pill-height`, so a new fixed or sticky bar at the bottom rises above it as `.ui-action-bar` does. Public data shown from a copy (the service worker's or the payment details kept in `localStorage` under `nfnn.payment-details`) says how old it is and that it "nemusí být aktuální".
