# Layout

Scrollbar gutter (`styles.scss`): from `nav` up, `html` reserves the scrollbar's strip (`scrollbar-gutter: stable`), so a page that does not scroll keeps the fixed header and the content on the same axis as one that does; the landing stage, which never scrolls, reserves none, so the hero runs to the window's edge, and neither does the launch screen, whose icon stays in the middle of the window as the launch image draws it. From `nav` up `html` carries the page's ground itself (`--color-surface`, `--color-surface-grouped` on the grouped pages, `--color-surface-inverse` while the contact section is in view, `--color-image-shade` on the landing), so the strip shows it, and while a modal dialog is open `html` takes the opaque colour of that ground under `--color-backdrop`, changing through `motion.state(background-color)` as the backdrop fades in (no transition under reduced motion) (`--color-backdrop-tint` mixed at `--backdrop-strength`, the scrollbar's track and thumb too; a gradient would not reach the strip, which paints only the canvas colour), so no bright strip stays beside the backdrop.

`chunk-load-notice/`: rendered by `app.ts` after the `router-outlet` while `ChunkLoadRecovery.failure()` is set, with the text "Stránku se nepodařilo otevřít. Web byl mezitím možná aktualizován nebo vypadlo připojení. Zkuste ji načíst znovu." When the first page failed (`initial`; the router has activated nothing, so no shell is on screen), a page of its own: `main#obsah.ui-panel-page` with a `.ui-panel`, the `h1` "Stránku se nepodařilo otevřít" (focused; the tab title becomes "Stránku se nepodařilo otevřít | Nová naděje – nadační fond" until the router sets the next page's title), the rest of the text as the lead, the button "Načíst znovu" and the link "Přejít na úvod" (`href="/"`, a full load). After a later navigation, a bar over the page (`.chunk-load-bar.ui-notice--alert.ui-notice--floating`, fixed at the bottom, at most `--measure-prose` wide and centred) whose button "Načíst znovu" takes the focus and is `aria-describedby` the message, so the message is announced once, with the focus move; the bar is no `role="alert"`, because an alert would announce the same text again and a screen reader that cuts speech short on the focus move could drop it; when the focus cannot reach the button (an open modal `dialog` makes the page behind it inert and leaves it out of the accessibility tree, so no region of the bar would be announced either), the bar hands the message, read from its own rendered text so the one i18n id `layout.chunk-load.message` serves both, to `DialogAnnouncer`, whose region inside the open dialog announces it, and withdraws it when the bar goes; the notice itself renders no status region, so a page's own status region stays the only one; while it shows, `:root` carries `has-floating-notice` and `--floating-notice-height` (measured, kept by a `ResizeObserver`; the themes set it to `0rem`), which add that room below the page (`body`'s `padding-bottom` on every page but the landing page, whose photo keeps its own room) and to `scroll-padding-bottom`, and a `focusin` listener scrolls a control the bar would hide above it in the next animation frame, after a left field has added its error line (Chromium does not scroll an element that is already in the viewport behind a fixed bar), never further than the control's top reaching the top of the visible band (the page's `scroll-padding-top` under the header plus the control's `scroll-margin-top`), so a control taller than the room between the header and the bar, such as „Starší“ at the largest text, keeps its top in view instead of rising under the header (#2076), leaving controls in an open `dialog` alone, so the bar never covers the end of the page or the focus (WCAG 2.4.11). It skips a `[tabindex="-1"]` element that only catches the focus (`main#obsah`, where iOS hands the focus at a press), never a control or an element with a `role`, so a radio the arrow keys focus while it still has `tabindex="-1"` is uncovered. In that frame it measures the element focused then, not the one the event named, so a press whose focus `PageFocus.keepOnPressed` returns to its button never runs the page to its end (#2004). A reader standing at the end of the page when a bar appears is kept at the end the same way as when the Offline pill appears (`keepThePageEnd`, #1964). While the on-screen keyboard is open (`html.keyboard-open` of `SoftKeyboard`), every `ui-notice--floating` is clipped away with `clip-path: inset(50%)` (`styles/ui/_notice.scss`), so a notice the keyboard carries up over the field being typed into never covers it (#2082). The `focusin` listener then lifts nothing: its frame returns at once while the root carries `keyboard-open`, because the clipped bar keeps its box and a field moved to with the keyboard up would otherwise be lifted above a bar nobody sees; the first focus, before the keyboard rises, is still lifted as above. Nothing scrolls when the keyboard comes or goes, so a drag while typing is never scrolled back and the scrolling of an open `dialog` or of the payment panel is not fought; the room the page keeps for the bar stays, so the page does not move, the Offline pill drops the bar's height from its offset meanwhile (`:not(.keyboard-open)` in `offline-status.scss`), so it does not float above an empty gap, and the notice stays in the accessibility tree, so a screen reader still hears it, and shows again as soon as the keyboard goes down or the focus leaves the text field.
